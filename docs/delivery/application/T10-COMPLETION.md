# T10 按公司名免费找企业与身份核实

## 交付范围

- 终端企业管理员和业务员可从工作台按公司名与三位国家代码逐页调用腾道 `/v2/company/list`；每次请求固定一页，页面大小不超过 20。
- 上游请求逐字段使用 `name`、`countryCodes`、`pageNo`、`pageSize`。公司列表响应只读取 `data.content`，没有用详情、联系人或其他接口字段兜底。
- 搜索页与候选分别按终端企业持久化。候选初始均为待核实；多个候选不自动选择，用户必须明确确认一个候选，未选择项仍不能通过已核实准入断言。
- 免费查询记录共享账号数据类调用次数及脱敏审计，但不写内部点数流水。共享令牌、跨接口每分钟守卫和数据/业务每日计数由 Redis 原子操作承载；业务类每日上限必须按账号配置，未提供演示值。
- 腾道 API key 和访问令牌只在服务端及 Redis 中使用，不返回浏览器、不写审计；40302 只刷新令牌并重试一次。
- 本票没有实现付费企业详情、建档、联系人查询或邮件发送。后续入口必须调用 `assertVerifiedCandidate`，待核实或其他企业的候选均被服务端拒绝。

## 已验证业务流程

1. 两页查询分别把原始 `name=ACME Query Name`、`countryCodes=USA,TUR` 和对应页码提交至 `/v2/company/list`；没有出现 `companyName` 或 `countryCode3`。
2. 两次免费数据请求复用同一个共享令牌：令牌接口计 1 次业务调用，列表接口计 2 次数据调用。
3. 使用彼此不同的本地候选 UUID、腾道来源 `id`、查询公司名、返回公司名和国家值，确认选择到准入的数据来源没有互换或增加兜底。
4. 两个歧义候选均以待核实保存，没有自动首选；确认第二项后只允许第二项通过准入，第一项仍拒绝联系人/发信前置检查。
5. 其他终端企业不能读取或核实本企业候选；无效字段、错误国家格式、首尾空格和伪造 `id` 在供应商调用前拒绝。
6. 两页成功调用写入两条免费调用审计，`chargedInternalPoints=0.0000`，采购/点数流水数量保持不变。
7. `npm run typecheck` 与 `npm run build` 通过；T10 供应商边界测试及真实 Nest HTTP + PostgreSQL 场景 2/2 通过；Chromium 从登录、填入公司名/国家、歧义提示、选择第二候选到下一页查询的 UI 场景 1/1 通过。

## 未验证与外部前置

- 未使用正式腾道账号、书面分销授权、生产 API 地址或真实候选数据；实际权限、结果覆盖、有效期和商务配额仍由 T29/T30 正式核验。
- 未在真实多实例 Redis 部署下做竞争、故障转移、跨日与容量测试；本票只实现原子共享计数/锁并验证客户端调用行为。
- 未执行真实联系人查询或发信，因为两者分别属于后续票据；本票只验证可复用的服务端身份准入门。
- 没有验证付费详情、点数冻结/结算或建档，且没有为这些后续能力预建入口。
- 尚未与后续付费详情、企业档案导航、联系人和发信页面做浏览器串联回归；这些入口不属于本票。
