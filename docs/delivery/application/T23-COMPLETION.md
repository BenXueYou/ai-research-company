# T23 经 U-Mail 发送同一单轮流程并跨渠道共享额度

日期：2026-10-27。范围：Spec US-50、52～55，PRD R30～31、R47～52，AT-14～16 的域名渠道及跨渠道额度分支。本地实现与受控适配器验证完成；未提交、推送、部署或修改线上工单。

## 实现

- 档案内已确认的 T21 预览可在同一 T22 确认页面明确选择本企业可用的 U-Mail 域名渠道。批次固定渠道、企业 U-Mail 资源、发信地址、回复地址、预设附件 ID 和逐收件人渲染内容；执行前再次核对渠道与资源。仅执行已确认单轮，不自动轮换或跨渠道重发。
- SMTP 与 U-Mail 复用 `email_daily_usage`、`email_usage_events` 及企业行锁，按北京时间日期和大小写不敏感去重邮箱数原子预占。受理转已用、明确未提交释放、不明或返回归属不一致保留原日预占；重复执行不再次提交。
- U-Mail 受控发送边界每次接收一个收件人，携带明确的企业与资源标识、`relpy_to`、本次渲染主题正文及按快照顺序映射的预设附件 ID/内容。不传公共 `tpl_id`，不读取公共模板最新版本覆盖本次编辑，也不自动附加档案或人工记录附件。适配器返回须匹配企业、资源和收件人标识。
- 默认发送适配器返回 `not_submitted`，没有正式供应商发送能力；U-Mail 真实资源隔离、小批量任务路径、内容生效、附件兼容、回执与回复实收留给 T32，证据核对和重发留给 T24，次日重确认留给 T25。
