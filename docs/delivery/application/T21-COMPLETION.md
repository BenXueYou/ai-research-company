# T21 收件人准入、去重冲突与本次邮件预览

日期：2026-10-27。范围：Spec US-42～49、PRD R26～29、R49～51、R62～63；AT-13 和 AT-14 的收件人及预览分支。

## 实现

- 档案联系人保留供应商 `mailsouId` 与原返回企业名。归属不一致逐条填写说明后准入；若后续返回企业名变化，旧说明不再作为当前来源的准入依据。退订标记作用于单条联系人，默认不选，手选须确认提示。
- 联系人页提供企业/个人邮箱明确选择。无企业邮箱不自动兜底个人邮箱。草稿及预览只读取本企业档案中的内部联系人 ID，再取联系人记录中的原始邮箱与 `mailsouId`；同批按邮箱整体小写比较键去重，变量冲突须手选该邮箱对应的联系人作为来源。加号和圆点保留。
- 公共模板选择后复制主题与正文为本次草稿；预览重新从当前联系人、模板版本及预设附件引用校验，缺变量或空值阻止生成及确认。用户确认锁定本次预览快照；草稿在预览后修改须重新预览才能确认。不修改公共模板、不发信、不占日额度、不扣查询点数。
- 平台公共模板受控预配工具写入不可变版本、主题、正文及预设附件；仅平台管理员已改密会话可执行。附件存私有数据库列，外部只列元数据，不开放下载入口。单文件 2MB、每模板 10 个、总量 20MB 均在服务端核验；不设产品格式白名单。预配前必须通过配置的安全扫描程序，记录 SHA-256、扫描时间、两年到期时间及模板版本审计。到期不自动删除；平台管理员可手动清理到期内容并留下审计。

## 平台维护操作

1. 在授权维护环境设置 `DATABASE_URL`、有效的 `PLATFORM_MAINTENANCE_SESSION` 和可执行扫描器路径 `TEMPLATE_ATTACHMENT_SCANNER`。会话来自平台管理员正常登录且完成首次改密；不可把令牌写入清单或日志。
2. 准备 UTF-8 JSON 清单，例如：

   ```json
   {
     "name": "初次联系",
     "subject": "您好 {{contactName}}",
     "content": "{{companyName}} 的合作邀请",
     "attachments": [{ "path": "./approved.pdf", "mimeType": "application/pdf" }]
   }
   ```

   `attachments[].path` 相对清单目录，扫描器以该文件绝对路径为唯一参数，退出码 0 表示扫描通过。工具读取内容后检查扫描期间文件未变。版本更新须提供首次输出的 `templateId` 与相同 `name`；可用 `attachmentIds` 引用已扫描、未到期的预设附件。执行：`node --env-file=.env node_modules/tsx/dist/cli.mjs --tsconfig tsconfig.server.json server/public-template-cli.ts provision <manifest.json>`。
3. 输出 `templateId`、`version`、`attachmentIds`。终端企业从档案写信入口读取当前版本并复制为草稿。到期清理执行同一脚本的 `clean-expired <attachment-uuid>`；到期仅标记，管理员明确执行后才清除私有内容。
