## 导航与生命周期

- `App.vue` 维护 `path`、监听 `popstate` 并手动调用 `pushState` / `replaceState`。取消浏览器后退时当前实现会重新压入原路径；迁移后须验证取消时 URL、历史位置及输入均保持正确。
- 工作区首次访问后以 `v-show` 隐藏兼容组件，账号设置和帮助往返不销毁这些实例；上游独立页面 `/platform/reconciliation/upstream` 与兼容监控不同时挂载。兼容容器不等同独立业务页。
- 未登录和强制改密界面共用当前地址；登录成功后普通会话进入角色默认页，已有会话直达合法链接保留目标。Vite 和 Nest 当前使用各自的明确路径清单提供 History 回退，包含上游监控路径。
- 当前离开确认只覆盖账号设置密码输入及提交中的公共状态，不能据此宣称所有业务表单已有离开提示。结果不确定的改密状态不跨刷新保存。

## 请求来源与幂等上下文

以下为现有前端代码的静态对照；具体值、权限拒绝、业务结果和调用次数需在独立测试库中通过浏览器迁移前后验证。

| 流程 | 现有请求字段及来源 | 生命周期风险 |
| --- | --- | --- |
| 直属组织状态 | `organizationId` 来自所选 `child.id`；`active` 为 `!child.active` | 不得将组织标识替换为账号标识 |
| 重置管理员密码 | `accountId` 来自所选 `child.accountId`；每次调用生成 `requestId` | 结果不确定时提示核实，不自动重发 |
| 直属开户 | 表单的 `name`、`kind`、`countryCode`、`phone`、`email` 和组件内 `requestId` | 关闭凭据后生成新的 `requestId`；切页不能丢失未确认请求上下文 |
| 企业身份核实及详情报价 | 两者的 `candidateId` 均来自所选 `candidate.candidateId` | 不得从其他 ID 字段推断 |
| 详情执行及档案刷新 | 执行 `queryId` 来自报价；刷新报价的 `profileId` 来自所选 `profile.id` | 不能因切页自动重放收费操作或丢失待核对上下文 |
| 点数订单 | 新建的 `buyerId` 来自表单；改单、收款、划拨及退款的 `orderId` 来自所选订单的 `id` | `pending` Map 按请求路径及请求体保存 `requestId`，成功后删除；兼容实例不能因路由切换重建 |
| 本人改密 | 三个密码来自对应表单；本人由服务端会话确定，不提交账号 ID | 成功后退出；失败结果不明确时禁止当前页面重复提交 |

现有 #35 交付记录记载了独立测试库中不同组织 ID、账号 ID 和父组织 ID 的历史验证，以及开户响应丢失后重试复用请求体的结果；这些历史结果不能代替 Router / Pinia 改造后的回归。#45 记录上游监控无自动供应商调用及显式刷新结果，同样需要针对改造后复验。
