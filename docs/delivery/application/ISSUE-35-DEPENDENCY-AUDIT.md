## 接入契约

- App 调用 `provideFormLeave(router, enabled)`；业务模块调用 `useFormLeave({ state, discard, active?, message?, retainUnknown? })`。状态由业务模块根据原始业务事实确定，公共层不判断请求字段。
- `clean` 自由离开；`dirty` 询问继续编辑/放弃，取消保留输入和历史位置，成功导航后才调用 discard。后续守卫拒绝导航不会清空草稿。同组件参数切换也经过同一保护；路由已经切换使状态变 clean 时，仍执行先前已批准的放弃。
- `submitting` 阻止离开；`unknown` 默认阻止，只有所属模块明确保留请求上下文且设置 `retainUnknown: true` 时才允许确认离开。公共层不会自动取消、退款、释放预留、重发或视为成功。
- 仅按必要范围在 App 的 KeepAlive include 中加入实际组件名称；停用的 dirty 表单不拦截其他页面，结果未知/提交中上下文仍参与退出及 beforeunload 保护。组件注销移除登记。缓存不保证完整刷新后恢复。
- 退出先取得 `prepareLeave()` 返回的提交函数，真实退出成功才执行放弃；401、成功改密、退出及账号切换清除会话，generation 变化销毁缓存，失效会话不由普通确认继续保留。
- `discard` 只清理未提交输入，不改变原业务请求、账务或未知结果。若批准后状态已变为 submitting/unknown，不执行放弃。
