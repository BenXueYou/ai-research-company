## 来源与范围

- 基线：Spec v1.2 身份/权限部分、US01～03/16～18、AT-01/02/03/05，PRD v3.2 R40～43、R70/74/75，技术设计v3.3第二章、第三章组织/联系信息/账号/凭据审计，docs/decisions/001-t01-identity.md，.scratch/phase1-ticket-plan.md T02。未用旧线上票覆盖本地规则。
- 名称与类型沿用既有开户字段（原型V2 childModal/accountCreateChild）；原型仅作为既有字段和active=true首位账号行为来源，不是权限或正式验收证据。新增组织启用，首位账号启用且必须改密，与开户后可登录的R70一致；没有开放用户选择状态或角色。
- 平台→一级分销/终端；一级→二级分销/终端；二级→终端；终端/业务员无开户权限。上级从锁定后的当前账号organization_id取得，客户端无parentId入口。数据库触发器阻止关系、类型与级数变更。
- 首位管理员角色由组织类型确定：distributor→distributor，terminal→admin。没有手填密码、公开注册、越级创建、迁移、成员管理、重置、点数或供应商调用。T05仍撤出一期。

## 实现

- `GET /api/organizations`返回当前组织的直属下级、脱敏电话、管理员邮箱与允许创建类型；`POST /api/organizations`创建组织和首位管理员。继承默认身份、来源及CSRF守卫，事务中再次校验锁定账号、会话、组织启用状态和层级。
- 组织、账号、开户请求标识、成功审计同事务提交。邮箱数据库唯一键沿用仅域名小写规范；电话唯一键基于原始区号与原始电话组合的带密钥摘要，覆盖跨组织及并发。电话无空格规则前后端拒绝，不裁剪、不补零/去零、不删标点、不推测号码格式。区号为显式+及1～3位数字，表单默认+86，可选择或输入其他区号。
- 电话AES-256-GCM加密保存，组织ID作为关联数据，列表脱敏。`ORG_CONTACT_KEY`须通过安全配置提供32字节密钥，数据库绑定指纹，不允许直接换钥改变唯一性。部署脚本校验配置，启动校验密钥一致性。没有提交运行密钥。
- 临时密码使用现有密码学随机源，24字符、72小时有效，只存scrypt摘要。首次返回及当前页面内存中交付；GET、审计、日志不提供密码。关闭、退出、进入账号设置或刷新会销毁交付界面，不支持回查。
- 前端同步busy保护、服务端actor/requestId唯一约束与事务重复检查防止重复开户；复制失败只重试剪贴板。响应丢失后的相同请求返回409，不回放凭据。列表可核实组织已创建，补发需后续T04。
- 为新组织补齐登录/会话/改密的组织启用检查，停用不级联下级。不增加停用UI，状态测试使用夹具；本人改密目标仍只由会话确定。
- 新库初始化包含T02结构，保留T01内置账号/重复初始化语义。不升级T01旧实验表；检测不兼容结构回滚，不删库或覆盖现有数据。

## 参数来源证据

| 参数 | 取值链路及验证 |
|---|---|
| name/kind | 浏览器原始表单值→POST→组织记录；类型受服务端当前层级限制 |
| countryCode/phone | 表单独立值→无空格校验→原值组合加密/判重；集成测试实际解密比对，无号码转换 |
| email | `Browser.N+admin@EXAMPLE.COM`等差异输入→POST原值→仅域名小写的账号邮箱→成功页→真实系统剪贴板→登录账号输入；本地大小写、加号、圆点不合并 |
| parentId | 当前会话账号→事务锁定accounts.organization_id→组织parent_id；平台和分销的不同组织ID、用户ID比对，不使用账号ID替代组织ID |
| accountId/organizationId | 分别独立UUID；账号归属、成功返回与审计目标比对，跨组织/跨级伪造目标字段拒绝 |
| password | 服务端生成→当次交付→真实登录→强改密；旧临时密码失败。电话、组织标识不参与登录邮箱推导，API未知字段拒绝 |

没有发信字段或供应商请求；不以发信地址兜底登录邮箱。业务拒绝路径检查组织数量和孤立组织，不只检查页面提示。
