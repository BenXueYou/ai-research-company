## 实现逻辑审计

本轮功能代码中有两处需要后续复核，但不应为了“顺手整理”继续延长本次会话：

1. 公司名页与产品词页的选择、请求标识保留、保存结果链接和提示样式存在相同逻辑。它们属于同一业务模块，后续若两处继续演进，可在 `web/pages/companies/components` 或模块内 composable 提取；当前不能在票02尚未完整复核时再做抽象重构。
2. 票02升级器同时处理未纳管旧结构、票01 baseline 和当前新库结构，分支较多。必要状态不能删除，但在恢复实施前应以三个明确夹具逐一验证，并检查失败事务不会留下版本或快照；不应继续增加“猜测结构”的兼容分支。

这两项是复核点，不授权改变请求字段、来源映射、默认值或业务条件。

## 后续票据的执行上限

每张票在编码前先写出最多四层验证矩阵：

1. 触及文件的静态检查或严格编译。
2. 一条核心公开接口测试，覆盖允许、拒绝、标识来源、账务和外部调用次数。
3. 一条真实浏览器主流程；响应式只在同一运行中切换宽度，不为每个宽度重启服务。
4. 直接受影响的既有回归；运行前确认其数据库、静态页面、端口和配置前置。

同一命令最多修正并重跑三次；第三次仍失败时停止扩张，记录失败属于实现、测试定位还是环境。已经确认的全局既有阻塞只复现一次，不反复运行全库命令。每票只保留一个编译目录，完成或中止时停止服务并删除一次性数据库、浏览器脚本、截图和编译副本。
