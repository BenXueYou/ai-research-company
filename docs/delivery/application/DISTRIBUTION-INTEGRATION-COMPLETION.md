## 组合场景与业务结果

平台通过真实开户/强制改密创建一级 A、二级 A2、A2 直属终端和旁支一级 B。每个组织 ID、首位账号 ID、订单 ID、收款引用与产品查询引用刻意不同；密码和会话不进入证据。开户 API 夹具仅用于建立合法组织链，浏览器开户完整交付沿用 #48/#49 的已执行证据。

平台真实销售用途采购 100 点/100 元，向 A 完整划拨 20 点、单价 2。两级分销均在浏览器依次完成：登录默认下级管理 → 直属详情（id query取组织而非账号）→ “点数订单与售价”链接（买方保持空选项）→ 后退到原详情 → 多层账户及面包屑 → 点数订单选择直属买方/数量/售价 → 建单 → 收款已落库丢响应 → 交易与利润 → 下级管理/账户 → 后退/前进 → 返回订单 → 主动重试原请求 → 停用买方 → 划拨拒绝 → 恢复 → 完整划拨 → 利润/CSV → 账号设置返回 → 刷新下级列表/账户 → 深链刷新 → 退出换账号。
