# 本地票02交付记录：当前页名单显式入库为初始企业档案

日期：2026-10-31。范围仅为 `.scratch/experience-optimization-20261031/issues/02-initial-profile-import.md`；未实施票03的重复企业关联或同名歧义选择。

## 完成结论

票02本地主流程通过，可以关闭本票并开始票03。公司名搜索和已取得的产品词名单均只在用户显式提交后入库；初始档案立即进入企业档案列表和既有详情页，并以“身份待核实 / 企业详情未获取”呈现。入库不调用上游、不冻结或扣减点数。

本结论基于受控本地名单、独立测试库、HTTP 契约测试和此前完成的真实 Chromium 主流程，不代表真实供应商或生产环境验收。此前浏览器截图及一次性脚本已按清理要求删除，不作为持久证据。

## 实现

- 新增 `POST /api/company-profile-imports`，请求仅接受 `requestId` 与 `items[{sourceKind,sourceRecordId,decision:'create'}]`。
- 新增档案来源与请求幂等记录；保存来源原文、搜索条件、页码、操作账号及首次响应。
- 初始档案允许详情、详情查询和企业国家为空，使用 `identity_state='pending'`、`detail_state='absent'`；既有详情档案升级后保持 `verified/ready`。
- 公司名页和产品词页在取得当前页后默认全选，允许剔除，再由主按钮显式保存；保存成功项提供初始档案入口，拒绝项显示名称和刷新重试提示。
- 初始档案沿用既有列表、详情、人工维护、时间线和附件结构；身份待核实时隐藏联系人入口，详情未取得时隐藏主动更新详情入口。
- 产品词的 `buyerCountryCode3` 只保存在搜索条件中，档案国家保持未知；未实现票03的跨来源自动关联或同名选择。

| 环节 | 实际值与来源 | 验证结果 |

| 来源证据 | 保存候选原文、查询条件、页码和操作账号 | 公司名、产品词两类来源均已断言 |
| 幂等 | 同请求标识与内容返回原响应；改变内容返回 409；同来源并发受锁和唯一约束保护 | 并发结果为一项 `created`、一项 `linked`，且 `profileId` 相同 |

| 外部与账务 | 入库只读取本地候选和搜索页 | 入库前后上游调用次数、点数流水、余额和冻结值不变 |
