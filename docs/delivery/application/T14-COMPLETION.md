# T14 档案内逐页获取联系人与归属标记

日期：2026-10-27。追溯：US-34、US-40、US-41；R24、R26、R46、R53、R62；AT-08、AT-09、AT-10、AT-11、AT-13 中的联系人获取、费用与归属标记范围。

## 交付

- 已确认企业档案的联系人页签支持职位标签、逐页报价与单页费用确认。职位接口枚举保留 `TECHNOLGY`，适配器以逗号拼接多值；供应商响应只解析 `data.list`。
- 报价锁定档案已核实名称、职位标签、页码、页大小、系数及最高扣点。执行前检查终端组织、档案状态、报价快照与可用点数；原子冻结后仅调用一次。重复执行及未知结果不自动重发。
- 持久化 `mailsouId`、原始返回企业名、邮箱与个人邮箱、职位、可信度及完整源响应。返回公司名不同的联系人标为归属待核实，页面没有默认选择或收件人准入动作。
- 成功页按受控适配器提供的实际扣点封顶结算，无邮箱不退款；真实零结果释放全部冻结；最终失败须平台携证据核对后释放。生产供应商响应不证明实际扣点，保留冻结待对账。本企业再次查看已取页免费。

## 已执行业务验证

- 独立 `acquisition_t14_test` PostgreSQL 库，Nest HTTP、真实会话与事务：无接口价格、异企业档案、余额不足均拒绝且无供应商调用；并发及重复执行仅一次调用并产生一次冻结、结算、释放；本地再看无调用无扣点。
- 供应商请求明确为 `companyName=Verified Profile Name`、`positionTag=TECHNOLGY,PURCHASING`、`pageNo=1`、`pageSize=20`。源列表 ID 为 `list-id-404`，详情 `data.id` 为 `detail-data-id-909`，内部档案 ID 为 UUID，联系人 `mailsouId=mail-source-707/708`，无关 `id/fileId` 均不同。参数来源与档案选择快照一致，未以其他标识替换。
- 控制价格 0.2500、最高计费量 2、X=1.0000：确认上限 0.5000；成功页实际上游 0.4000，内部扣点 0.4000，余额 2.0000→1.6000，冻结回到 0；其中一名联系人无邮箱，仍保存且结算。`total=200` 仅显示达到单企业返回上限。
- 下一页超时保持 0.5000 冻结且重复执行不重发；终端成员不能核对最终失败，平台提供依据后仅一次释放；真实零结果全额释放。异企业不能查看档案联系人。
- Chromium 从登录到本地档案页签，选择 `TECHNOLGY`、查看报价、确认本页、展示归属待核实/可信度和刷新点数摘要通过。浏览器请求的 `companyName=Chosen Company` 来自档案名称，与列表 ID、详情 ID、联系人来源 ID 不同。
- `npm run build` 通过；`company-contacts.test.ts` 两项通过；`company-contacts.spec.ts` 一项通过。既有 `.env.test` 测试库使用旧身份表结构，首次启动失败；上述通过结果使用独立新库。
