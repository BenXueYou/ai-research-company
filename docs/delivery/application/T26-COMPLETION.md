# T26 组织停用时协调在途查询、邮件及待划拨订单

日期：2026-10-27。本地实现；未提交、推送、部署或修改线上工单。追溯：Spec US-79～80；PRD R43；AT-05、AT-21 的组织状态范围。

## 实现与业务边界

- 直属上级在下级列表停用或恢复直属组织。服务端重新核验账号、会话、角色、管理关系和组织状态，事务记录状态变更；重复操作不重复写事件。停用撤销该组织成员会话，登录与新业务拒绝。下级组织状态不级联修改。
- 停用事务把该组织尚在 `queued` 的邮件收件人改为 `paused`，释放其所属日期的预占并记录额度事件。`submitting`、`uncertain` 等已提交或结果不明收件人保留原日额度和证据流程；停用不调用重发或核对接口。恢复后暂停邮件仍需原发送人手动重确认；T25 跨日暂停仍要求后续日期重确认，组织停用造成的暂停允许恢复后在同日重确认。
- 查询在开始冻结前与组织状态锁串行核验；已冻结的 `pending` 查询保留冻结及原价格/系数，平台仍可按证据核对最终失败并释放。停用不把在途查询自动判断为成功或失败。
- 已收款待划拨订单保持 `reserved`、数量、售价与销售预留。直属买方停用时拒绝划拨，恢复后仍按原整单规则划拨；未收款订单不能在买方停用时调价或确认收款。停用上级不影响仍启用下级向自己下级的业务。退款仍是独立线下确认流程。
- 登录事务对组织加共享锁，和停用事务串行，以便撤销停用前创建的会话。前端展示直属买方停用造成的划拨暂停。

## 验收证据

- 独立 PostgreSQL 库 `acquisition_t26_final6_test`、端口 `3196`：真实 HTTP 验证直属授权与越权、登录失效及恢复、未级联下级、订单预留保留与恢复划拨、查询在途冻结及停用期间平台核对释放、邮件 `queued` 暂停与额度释放、`uncertain` 保留及恢复后手动重确认。一级分销停用后，仍启用的二级分销完成向自己直属终端的建单、收款预留和划拨。再次停用不重复扣减。余额历史不清零。详情查询的候选列表 `source_id=list-id-distinct`、详情 `detail_id=detail-id-distinct`、档案 UUID、账号 UUID、组织 UUID、邮件 `mailsou_id=mailsou-distinct` 均采用不同值；T26 状态提交仅取直属下级 `id`。

- 联合回归各使用独立测试库：T15、T18、T22/T23/T24/T25、T28 的 HTTP/PostgreSQL 测试通过；T16、T18、T24、T25 的浏览器业务测试通过。T26 的 HTTP 和浏览器测试通过。浏览器回归使用 T26 独立编译输出和端口，没有改写其他票的生成产物。
