# T11 单独确认企业详情费用并建档

## 已实现

- 已核实候选才可报价。详情 `name` 来自所选候选的 `source_name`，`countryCode3` 来自 `source_country`；列表 `source_id` 与详情 `data.id` 不参与请求参数替代。
- 报价读取 `/v2/company` 接口配置的单价、最大计费量及当前 X，锁定确认快照；生产环境仅接受 `supplier_verified` 价格。缺价格或无法形成正数上限时拒绝。
- 用户确认后，在 PostgreSQL 事务中锁定终端账户并冻结最高额度。重复执行同一授权不再次调用供应商；并发可用余额核验防止超用。
- 详情按 `data.id === null` 判断零结果；非空详情强校验 `countryCode3`，电话/网址空不影响可看结果。成功按实际上游扣点合计乘锁定 X 后取四位，且不超过确认上限；释放差额。零结果释放全部。
- 超时、供应商实际扣点不明、国家不一致或本地保存不明保留冻结和“结果确认中”，不自动重试。平台可凭最终失败依据释放，记录核对人、依据和时间。
- 档案按终端组织隔离并共享给本企业成员；本地再看不付费。点数余额、查询冻结、可用余额及最近查询流水可查看。

## 已执行业务验证

- 独立 `acquisition_t11_test` PostgreSQL 库，真实 Nest HTTP、会话鉴权和数据库事务：无价格、待核实候选、余额不足、跨企业授权拒绝均没有详情调用。
- `list-id-Selected Company Name`、内部候选 UUID、详情 `detail-id-901` 刻意不同；最终供应商请求准确为 `name=Selected Company Name`、`countryCode3=TUR`。原搜索词也与详情名称不同。
- 受控单价 0.5000、最高计费量 2、X=1.0000：确认上限 1.0000；实际上游 0.4567，扣终端 0.4567，余额 2.0000→1.5433，冻结 1.0000→0.0000；重复执行只调用一次、只写一次冻结/结算/释放流水。
- 真实零结果（`data.id=null`）释放全部；网络超时保持 1.0000 冻结且重复执行不重发；平台最终失败核对两次仅释放一次。另一企业档案库为空，且不能执行本企业授权。
- Chromium 从登录、免费找企业、明确核实、独立报价与确认，到详情档案和点数余额可见的 UI 流程通过。详情请求参数为列表返回名称及国家，和列表 ID、详情 ID 不同。
- `npm run build` 通过；`company-detail.test.ts` 通过；`company-detail.spec.ts` 通过。

## 未验证及外部前置

- 未使用正式腾道账号、账单、书面授权或实际单价。供应商详情响应没有可直接证明的实际扣点字段；生产调用会保留冻结等待账单核对，不会将接口报价冒充实际扣点。正式账单结算、长期未决人工核对期限及超额费用归集仍需 T13/T29/T30 的外部证据。
- 受控测试以明确夹具提供终端点数；T07/T08 的销售划拨、上级库存和完整商业旅程尚未串联验证。测试价格和余额不是生产默认值。
- 未验证真实供应商的返回国家字段覆盖率、跨实例故障恢复、供应商费用超额对账或生产多租户规模。国家不一致时保留冻结待核对，不自动建档。
- T11 只交付企业详情范围；联系人、下一页付费查询和产品词国家映射仍属后续票，不借本票开放。
