## 实际行为

- 初始化 CNY、X=1.0000、最低加价率 m=0.0100；接口价格为空，不填入示例价格。已有配置重复初始化不覆盖。
- `GET /api/procurement` 返回当前计价、库存余额/可用/冻结/预留、成本和最低售价、采购、费用关联、资金支出及只增流水。累计上游采购点数明确标为登记累计值，不冒充供应商实时余额。
- `POST /api/procurement/purchases` 从请求读取用途、上游点数、人民币金额、采购凭证和依据。销售采购按数据库当前 X 记录快照并生成内部库存；成本按 `(原余额×原单位成本+本次人民币金额)/(原余额+本次生成内部点数)` 更新，四舍五入至四位。补足额度、失败和超额充值生成内部点数为零，不改成本和最低售价。
- `POST /api/procurement/expenses` 按用途、来源编号、金额及依据登记一次费用。来源编号唯一，费用与资金支出分列。失败/超额充值须显式选择已登记费用；补足额度可以选择已有费用，或随本次充值确认新费用。已记费用可关联多笔充值，每笔仍有唯一采购凭证；关联充值不再增加费用。返回关联采购 ID 列表、充值合计及与费用金额的差额，保留不等额/尚未补足的核对状态，不自动推断差额费用。
- `POST /api/procurement/pricing` 可设置 m，或记录准确接口路径、上游点数单价、已核实本页最大计费量、依据和版本。生产模式拒绝 `controlled_test`，生产查询配置中也排除测试价格。`supplier_verified` 是运营提供商务依据的明确声明，系统未自动核验供应商合同。没有 X 修改入口；额外传入 coefficient/组织/账号等字段拒绝。
- PostgreSQL numeric 运算与 round(...,4) 处理金额、点数、系数和每点成本；不使用 JavaScript 浮点计算账务。上游点数先按字段精度取四位，再乘入账 X；沿用本票采购字段精度。查询按页汇总后取四位的规则没有被改写，查询结算本身由后续票实施。
- 事务内重新校验当前账号、组织、角色、必须改密状态及活跃会话；默认来源/JSON/CSRF 守卫继续生效。actor_id 来自会话账号。锁定全局计价和库存，更新库存、采购、费用、流水、幂等响应在同一事务提交；不同平台账号并发也串行核算。
- 原请求标识+原载荷重试回放同一业务结果；同标识改载荷拒绝。不同请求重复凭证/费用来源由数据库唯一约束拒绝并整体回滚。浏览器网络结果不确定时保留原请求标识重试。流水、采购、费用和幂等记录通过数据库触发器拒绝 UPDATE/DELETE；没有编辑/删除账务 API。
