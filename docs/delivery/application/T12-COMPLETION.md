# T12 按产品词、采购企业所在国和贸易时间找候选

## 已实现

- 首页新增产品词入口，输入产品词、采购企业所在国三位代码和贸易时间范围。每页先报价，用户确认后才冻结并调用最小进口商名称名单；翻下一页重新报价和确认。不自动批量建档，也不混入其他查询条件。
- 名单调用契约固定 `catalog=imports`，保留所选 `productDesc`、采购企业所在国、开始及结束日期、页号及页大小。`/v2/trade/importers-name` 结果只接受名称，不把商品目的国当企业所在国，也不把名称名单当完整企业身份。
- 采购企业所在国到上游筛选条件的映射尚无实证。生产入口未注册声称映射已核实的进口商适配器，因此在报价前拒绝付费调用；受控适配器须明确声明该能力，供本地流程验收。正式接入须先完成 T30 的国家映射、贸易方向、企业关联和计费证据。
- 有接口单价、最大计费量及系数快照才可报价；成功按实际上游扣点和锁定系数以四位小数结算，释放差额。真实零结果全释；响应无实际扣点证据、超时、结构异常或本地结果不明保留冻结及证据，不自动重试。重复执行不再次付费调用。本地已结算同条件同页可免费查看。
- 名称候选由用户逐个选择后，用现有免费 `/v2/company/list` 按该名称和所选采购企业所在国查企业；明确核实返回的名称与国家。国家不一致的返回企业不能通过核实。详情沿用 T11 的独立报价、确认和建档；详情失败或结果未决不回退已成功结算的名单费。
- 名单页、候选、冻结结算流水与免费核实关联按企业隔离。名单结果只含名称，不暴露贸易明细或量价。

## 已执行业务验证

- 独立 `acquisition_t12_test` PostgreSQL 数据库、3122/3123 端口、隔离的编译和浏览器输出：真实 Nest HTTP、身份会话、数据库事务和 Chromium 用户界面；供应商仅在适配器边界为受控响应。
- 无价格、无国家、额外商品目的国参数、余额不足、跨企业页执行及候选访问均拒绝，且未发付费请求。第一页确认后结算 0.4321 点，余额 3.0000→2.5679，三条冻结/结算/释放流水只写一次；重复提交只调用一次。第二页须再确认并独立扣 0.2000 点。
- 明确零结果本页扣 0；超时保留冻结，重复提交不重发。详情失败保持待核对，第一页名单费仍为 0.4321 点。
- 选择快照与最终适配器请求逐项一致：`catalog=imports`、`productDesc=ceramic pump`、采购企业所在国 `TUR`、日期 `2026-01-01` 至 `2026-06-30`、页号 1/2、页大小 20。免费身份核实请求 `name=Buyer Name from Trade`、`countryCodes=TUR`；列表标识 `list-source-id-42`、内部候选 UUID、详情 `data.id` 各不相同。详情最终请求名称来自已核实的列表候选 `Confirmed Buyer Legal Name`，国家来自该候选 `TUR`。返回企业国家故意改为 `USA` 时核实被拒绝。
- 浏览器从登录、第一页报价与确认、第二页再报价与确认、免费身份核实，到详情单独确认及本企业档案展示通过。受控前端构建及 T12 HTTP/PostgreSQL、浏览器测试通过。
