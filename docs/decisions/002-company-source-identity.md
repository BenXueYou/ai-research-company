## 业务规则

1. 内部档案 ID 承载跟进、附件、联系人和邮件；来源记录承载供应商记录及获取上下文。一个档案允许关联多个来源。
2. 同来源幂等指同一租户、来源类型、本地已保存候选引用；供应商列表 ID 不作为跨搜索、跨日唯一企业键。名称和国家只召回可能重复项。
3. 来源选择、档案关联和联系人/邮件准入分别记录。选择 A 只确定操作对象，人工关联只确定资料归档；两者均不自动证明唯一企业或联系人归属。保持身份 pending，直到独立证据满足该操作准入。
4. 同名同国 A/B 资料不足时可关联已有档案、单独建档或暂不处理；单独建档不是确认不同企业。资料缺失不构成一致或冲突。可靠企业键仍须有类型、适用范围和稳定性证据。
5. 精确详情从服务端已保存的候选 source_id 取供应商记录标识，本地 candidateId、profileId 各司其职。请求固定来源、目标档案、选择版本、名称、国家和供应商记录标识；返回 data.id 与所选记录不符或国家冲突时保存证据、不发布。data.id=null 沿用零结果规则。失败不自动换名称路径。
6. 详情按来源及查询保存不可变快照。原档案没有详情时可发布首份有效资料；同一展示来源主动更新可刷新；不同来源的新资料保留为可选资料，由用户明确选择展示，不能后到覆盖先到。人工字段独立保存。冲突资料不能选作展示资料。
7. 详情 ready 与费用状态分开；费用未知保留冻结，但有效资料可读。结果迟到、零结果及失败不删除原档案或旧有效资料。旧账务及最终失败处理不因本修订变更。
8. 联系人仍使用原 companyName 来源。完整名称或已选列表 ID 本身不足以证明同名联系人的归属；证据不足拒绝对应联系人及发送入口。保留已有逐联系人归属说明、邮箱、退订、去重及额度规则。不要把“付费取得详情”作为解决歧义的替代条件。
9. 旧记录保留 ID、人工字段及历史；旧 identity_state 默认 verified 不作为证据。迁移不批量制造已核实身份，不自动合并历史。旧名称详情路径独立保留并标明语义，不能用于精确 A/B 请求的兜底。

## 验收

- A/B 相同名称国家、不同供应商 ID，内部候选/档案 ID 均不同；独立选择、精确调用和返回对应性。
- 同来源重复提交/并发只归属一个档案；不同来源同名不自动合并；人工关联不自动放开联系人或邮件。
- 过期选择版本、跨租户、删除、停用、来源变更在报价及派发拒绝；同一授权重试不重复供应商调用。
- 有效详情先到而费用未到可读；零结果保留原档案；ID/国家不符保留证据而不覆盖；同档案 A/B 两份快照并存，展示切换不改人工内容。
- 原人工内容、联系人、沟通、附件、邮件、余额及账务按适用操作前后对照。名单保存/关联/选择展示零上游调用、零扣费。
- 跨日同 ID 与换 ID 均不自动升级企业身份。受控变化测试与真实跨日观察分别记录。
- 真实页面宽屏、中间及手机宽度验证；正式联系人归属和准确 ID 请求契约未齐时明确未验收。
