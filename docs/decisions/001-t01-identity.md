# T01 身份规则决策

日期：2026-10-26。状态：用户在实施会话中明确批准。

对应工单：https://github.com/BenXueYou/ai-research-company/issues/2 。批准时基线：第一阶段 Spec v1.0、PRD v3.1。2026-10-27已回流至PRD v3.2、技术设计v3.3及Spec v1.2；身份参数适用于T01～T05；2026-10-27用户后续确认平台初始账号例外，以下初始账号条款覆盖原“邮箱+随机临时密码”引导约定，其余身份规则保持有效。前端构建与组件选型按技术设计执行。

## 已批准规则

- 技术栈：Vue 3 + TypeScript 前端、NestJS 后端，PostgreSQL 持久化。
- 新密码长度为 12～128 位，仅允许可打印 ASCII 字符（英文、数字和常见符号），不允许空格；拒绝与当前密码相同。
- 下级开户、成员创建及授权重置的临时密码采用密码学安全随机源，24 个字符，有效期 72 小时；平台初始账号的首次密码采用下述明确例外。到期不得认证，只能通过授权重新生成；管理方重置属于后续工单；平台恢复逻辑已撤出一期。
- 登录邮箱仅域名部分统一小写，本地部分保留大小写；不合并加号别名、不删除圆点。认证和数据库唯一键使用同一规范。不得以电话或发信地址代替登录邮箱。
- 会话最长 8 小时，连续空闲 30 分钟失效。本人改密或管理方重置后，该账号所有设备会话失效。后续重置功能必须复用此规则。
- 初始平台账号由数据库初始化过程内置创建（仅部署环境执行，无公开初始化接口）：登录名为`super_admin`，首次初始化密码为`init@Base123`。这是用户确认的唯一非邮箱登录及固定初始密码特例，不推广至下级或成员账号，不伪造登录邮箱。首次登录必须改密，之前只允许强制改密及退出；初始化密码沿用72小时临时凭据有效期。无公开初始化接口；重复引导不得覆盖已有账号密码，改密后初始密码不能继续登录。只持久化密码摘要，不记录明文到日志或审计。

## 实现及验收边界

- 临时密码认证后仅允许本人强制改密及退出。服务端对业务请求同样拒绝。
- 本人主动改密要求当前密码及两次新密码；成功后重新登录。初次强制改密也使原会话失效，以新密码重新登录。
- 密码只持久化加盐摘要；审计不含明文、摘要或完整令牌。会话使用随机不透明凭据，数据库仅保存其摘要。
- 初始组织与管理员原子创建；并发引导最多成功一次。不以演示夹具作为生产入口。
- 首票只交付身份闭环与受保护的最小工作台，不实现下游开户、点数、查询或发信。
- 测试使用真实数据库，浏览器驱动真实后端；正式供应商调用不在首票范围。
