# 控制台导航设计讨论

日期：2026-10-28。状态：用户已确认整体共同理解；工作区已有公共导航等增量实现。此次同步 Vue Router / Pinia 技术方案，迁移尚未实施或验收。

正式实施规格见[控制台角色导航与页面迁移 Spec](../需求设计/10-控制台角色导航与页面迁移Spec.md)。本文保留讨论确认记录，后续实施以正式规格及其引用的既有业务契约为准。

## 用户已确认

- 四类角色统一设计：平台运营、分销管理员、终端企业管理员、业务员；分批实施，优先落地平台控制台。
- 平台登录后的默认页面为运营概览。
- 平台一级菜单与职责采用下表，已确认子页面见后文。

| 一级菜单 | 页面职责 |
| --- | --- |
| 运营概览 | 关键状态、异常摘要、快捷入口 |
| 下级管理 | 下级组织、直属开户、下级详情与定价 |
| 点数与账务 | 点数订单、平台采购、平台承担费用、交易与利润、账务流水 |
| 上游与对账 | 腾道账号状态、额度与有效期、查询异常人工核对 |
| 平台设置 | 接口单价、换算系数、最低加价率、企业邮件资源与日额度 |
| 帮助中心 | 操作指南、规则说明、常见问题 |

- 账号信息、账号设置和退出统一放右上角。
- 平台子页面按职责划分为：
  - 下级管理：直属下级列表、开户、下级详情、定价和管理员密码重置。
  - 点数与账务：点数订单、平台采购与费用、交易与利润、账务流水。
  - 上游与对账：上游账号监控、查询异常核对、迟到结果处理。
  - 平台设置：接口单价、换算系数、最低加价率、U-Mail 资源、企业邮件日额度。
- 菜单、子页面和快捷入口根据当前登录角色展示；前端展示控制不替代服务端权限校验。
- 分销管理员默认进入“下级管理”，导航为“下级管理、点数订单、交易与利润”。下级管理包含直属下级列表、开户、下级详情、定价和管理员密码重置；点数订单包含创建订单、收款确认、库存预留、完整划拨和退款；交易与利润包含授权范围内的交易、利润和自有账务对账。
- 平台与分销的直属下级列表展示点数摘要，并在“下级管理”内提供“下级账户”子页面，查看既有授权范围内多层下级的余额、查询冻结、销售预留及可用点数。分销查看范围不收窄为仅直属；查看不授予下级客户内容或跨级操作权限，平台业务数据查看例外按单独约定执行。
- 终端企业管理员和业务员共用六个入口：找企业、企业档案库、邮件发送记录、团队发信设置、成员管理、点数用量；默认进入“找企业”。企业管理员可维护团队发信设置、成员管理及本企业档案，业务员可使用业务流程和查看共享数据但不能维护团队设置或成员。
- 导航采用真实页面路由：平台 `/platform/overview`、`/platform/organizations`、`/platform/ledger`、`/platform/reconciliation`、`/platform/settings`；分销 `/distribution/organizations`、`/distribution/orders`、`/distribution/profit`；终端 `/terminal/search`、`/terminal/profiles`、`/terminal/emails`、`/terminal/sending-settings`、`/terminal/members`、`/terminal/usage`。刷新、前进、后退和复制链接保持当前页面；未授权路径由服务端与前端共同拒绝或回到角色默认页。
- 右上角“账号设置”进入独立 `/account/settings` 页面，提供修改密码；成功后按既有契约退出登录并使用新密码重新登录。首次登录或重置后的强制改密继续使用独立强制流程，不能通过业务路由绕过；返回后回到用户此前所在业务页面。
- 帮助中心四类角色共用 `/help`，按登录角色展示相关指南。平台保留“帮助中心”菜单，分销与终端在侧栏底部提供帮助入口；完整操作指南移入帮助，费用确认、风险提示、校验错误和当前操作必需说明保留在业务页。
- 平台“下级管理”增加“业务数据查看”子页面，按授权组织筛选客户档案与邮件记录，与直属下级操作分开。全链查看不授予跨企业修改、删除或发信权限，开户、定价和密码重置仍受直属关系限制。
- 开户、采购、订单或配置表单有未提交内容时，切换菜单、返回或浏览器后退先提示“继续编辑／放弃修改并离开”；首版不新增跨页面草稿保存。已提交但结果尚未确认的请求继续沿用既有核对与防重复提交机制，切换页面不视为业务取消。
- 运营概览采用“状态摘要＋待处理事项＋快捷入口”的轻量布局：
  - 状态摘要：平台点数库存、上游剩余点数与有效期，并标明上游快照获取时间。
  - 待处理事项：需要人工核对的查询、待履约点数订单，点击进入对应业务页。
  - 快捷入口：直属开户、点数订单、平台采购、异常对账。
  - 概览不承载完整表单和明细；进入概览不自动触发上游状态更新。

## 2026-10-28 路由与状态管理方案调整

- 用户明确要求采用 Vue Router；使用 `createWebHistory()` 保留现有 URL，统一路由表、RouterLink / RouterView、导航守卫、高亮和滚动行为，替换 App.vue 内手写 History 导航。
- 评估后采用 Pinia，初期只管理共享会话及初始化状态，供账号区、守卫和业务页使用。路由状态归 Router，表单、报价、结果未确认请求及业务数据留在所属模块，不做全局状态搬迁。
- 暂不引入 Pinia 持久化插件、自动请求缓存 / 重试库、自动路由插件或权限插件；刷新按既有 Cookie 会话重新验证，不保存密码或扩展跨页面草稿能力。
- 第一批先完成 Router / Pinia 与会话门禁，再分批拆业务页；兼容工作区实例和必要页面缓存须保持原业务上下文，退出、401 及切换账号清理旧状态并阻止旧请求回写。切页不能重放收费、邮件或订单操作。
- 同步核对 Vite、服务端和部署入口对深链的承载，覆盖 `/platform/reconciliation/upstream`、详情路径直达及刷新；不能用前端 Router 替代服务端配置。
- 完整目录职责、状态归属、迁移顺序与新增验收项见正式规格 v1.1 的“Vue Router 与 Pinia 技术方案”。本次只调整文档，不代表新增依赖已安装或路由迁移已完成。

## 现有契约与设计边界

- PRD R64 已明确终端首页聚焦找企业，R67 已明确分销三个入口；本轮确认的入口、默认页面与权限边界见上文。
- 采购入账、平台承担费用与基础计价目前同处一个组件；上述菜单划分要求后续按职责组织页面，不改变业务取值与校验。
- 上游账号状态现有页面读取最近快照；更新上游状态由用户主动触发。进入概览不应自行扩展外部调用行为。
- 保持请求参数来源、标识映射、权限、枚举、默认值、兜底优先级、校验和提交条件；本轮未授权改变业务规则。
- 公共 Vue Router / Pinia 基础迁移的实施与验证另见 [交付记录](delivery/application/VUE-ROUTER-PINIA-COMPLETION.md)；各业务拆页仍按对应批次验收。
