# T07 直属点数订单确认收款与原子预留

## 交付范围

- 卖方工作台列出有效直属下级、订单和自身库存；平台与分销管理员可建单、调整未收款订单、确认线下足额收款。
- 服务端重新核对登录会话、角色、双方组织状态和直属关系。建单与调整按当前平均成本和已生效最低加价率校验；确认时重新校验并在同一数据库事务中锁定库存、记录唯一收款凭证、预留和只增流水。
- 同一请求标识重放只返回原结果；同一收款凭证不能分配给另一订单。库存不足时拒绝系统确认，并明确提示线下款可能已到账，需人工核对。
- 收款后的数量和售价不可通过订单接口修改。实际划拨及买方入账属于 T08。

## 已执行的业务场景与结果

- `npm run typecheck`、`npm run build` 通过。
- `npx tsc -p tsconfig.server.json; node --env-file=.env.test --test dist/tests/point-orders.test.js` 通过。真实 HTTP、会话和隔离 PostgreSQL 覆盖低于售价下限、越权、成本变化后的旧价拒绝、重复确认幂等、重复收款凭证、库存不足和两单竞争剩余库存。最后库存 10.0000、预留 10.0000、预留流水 2 条，无超售。
- `node --env-file=.env.test node_modules/@playwright/test/cli.js test --config playwright.t07.config.ts` 通过。浏览器选择甲买方后，建单请求的 `buyerId`、订单持久化的 `buyer_id` 与所选甲组织 ID 完全一致，且与乙组织 ID 不同；数量 `3`、单价 `2.2` 对应持久化金额 `6.6000`，确认后预留 `3.0000`，流水 1 条。
- 测试中的最低加价率、库存与平均成本是显式受控夹具，不是生产默认值或正式价格依据。订单流程无外部付费调用。
