# T22 经国内 SMTP 手动单轮发送并共享企业日额度

日期：2026-10-27。状态：本地实现及独立 PostgreSQL、HTTP、Chromium 业务验收通过；未提交、推送、部署或修改线上工单。

## 实现

- 档案预览按 T21 的本人已确认快照进入本批渠道、退订提示和额度确认。服务端仅接受本企业已验证可用的 SMTP 渠道；固定模板版本、预设附件、逐收件人邮箱、内容、联系人及 `mailsouId` 快照入队。不读取公共模板最新版本覆盖本次内容。
- 平台按终端企业 UUID 配置每日上限并留下配置审计，未配置默认 2000。北京时间日期为额度键；确认时按最终去重地址数，在企业行锁及额度行锁下原子预占。企业成员和未来渠道共用同一企业额度表。
- 每个收件人只执行一次单轮。受控 SMTP 适配器返回受理后预占转已用，明确未提交释放，不确定保留；执行前进程中断留下 `submitting` 和原日预占，不自动重试。重复确认返回同批次，重复执行不再调用适配器。跨日尚未执行时暂停并释放原日预占，不自动推进客户状态。
- 发送批次、逐收件人状态与企业档案邮件时间线可读。邮件记录独立于人工时间线表，不提供手改、删除接口；人工记录编辑与删除入口也不显示在邮件项上。受理在页面明确不等于送达。
- 默认发送适配器明确返回未提交，避免未完成正式联调的运行环境真实发信。T31 需用真实国内 SMTP、DNS、允许的收件人和证据联调。

## 参数来源与业务结果

| 值 | 来源及核对 |
|---|---|
| 企业、操作者 | 登录会话 `organization_id`、账号 `id`；客户端不得提交这两个目标字段 |
| 档案与联系人 | T21 预览 `profile_id`、内部联系人 UUID；列表来源 `list-111`、详情 `detail-222`、源 `id`、`fileId`、`mailsouId` 均使用不同值，最终 SMTP 收件人保留用户选定邮箱和对应 `mailsouId`，未做标识兜底 |
| 去重邮箱与变量 | 快照 `emailKey=email.toLowerCase()` 计数；同邮箱来源由 T21 显式选择，测试中 `mailsou-1` 与选定内容进入发送适配器，两个大小写变体仅占一封 |
| 渠道与回复地址 | 用户所选本企业 `channelId` → 固定 `SMTP` 和 `reply_to`；不由登录邮箱或 SMTP 用户名推断，执行时渠道配置变化阻止未执行提交 |
| 附件 | T21 快照 `attachment_ids`，执行时只取仍有效的公共模板预设附件；不从档案或请求增加临时附件 |
| 额度 | 平台所选终端企业 UUID → `organization_email_limits`；测试上限 3，三地址执行后已用 1、保留 1、释放 1，未产生联系人查询点数流水 |
