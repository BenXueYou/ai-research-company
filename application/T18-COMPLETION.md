# T18 档案及人工记录附件的私有留档

## 已实现

- 本企业成员在档案上传、下载附件，并可把附件关联到同档案的人工时间线记录；WhatsApp 登记表单可同时选取附件。附件关联使用所选 `company_profiles.id` 和新建的 `timeline_manual_records.id`。企业管理员可软删除附件；单附件恢复入口不存在。
- 服务端核验终端企业、档案和人工记录归属；限制 jpg/png/webp、pdf/doc/docx/xls/xlsx/ppt/pptx、zip/rar 的扩展名、MIME 和文件特征，单文件 1 字节至 20MB，每企业最多 50 个未删除附件。按组织行锁序列化数量检查。文件名只存元数据，私有文件名由服务端随机生成。
- 上传文件进入静态目录之外的私有目录，安全扫描程序须明确返回成功；扫描期间文件不变才将文件和数据库元数据写入。数据库失败会补偿删除已写文件；下载重新检查 SHA-256，且只能经已鉴权接口取得。上传、下载、软删除、到期清理有独立审计。
- 默认保存两年，到期标记但不自动删除。有权限的企业管理员可手动清理到期文件，包括已软删除的到期文件；失败可再次清理。档案附件没有进入邮件预览或发送路径，T22/T23仍只使用T21公共模板预设附件。
- 部署入口和环境样例增加私有目录、扫描程序及参数配置。缺配置或扫描未通过时拒绝上传。

## 已验证

- 独立 `acquisition_t18_test` PostgreSQL 库、端口 3188 的真实 Nest HTTP、会话和持久化测试通过：正确上传/下载和 SHA-256 内容比对；跨企业/档案/人工记录访问拒绝；错误扩展名、MIME、文件特征、扫描拒绝、超过20MB、达到50个的服务端拒绝；扫描与数量失败不留下文件；普通成员无法删除或清理；管理员软删除幂等且只有一次审计；未到期拒绝清理，到期清理幂等并移除私有文件。
- 候选来源 `list-id-different`、详情 `detail-id-different`、档案 UUID、WhatsApp 记录 UUID 刻意不同；浏览器选中档案后的上传请求、数据库 `company_id` 与 `communication_id` 均核对为档案和记录 UUID。未改原有查询与邮件参数取值来源。
- Chromium 端口 3189 从登录、展开本企业档案、登记带 PDF 的 WhatsApp 记录、附件可见至下载并核对字节通过。Vue 类型检查、服务端 TypeScript 编译和独立 Vite 输出构建通过。未运行共享 `npm run build`，因同目录并行 T23 使用独立输出，避免写入共同 `dist`。
- 本票不涉及点数、金额或邮件额度；无新增点数/额度流水。

## 未验证及边界

- 尚未在正式环境部署和验证实际杀毒扫描程序、共享私有存储、多实例并发与备份恢复；测试扫描器是受控进程，仅证明拒绝与成功路径。文件系统目录必须作为私有持久卷由部署环境保护和备份。
- 未串联正式腾道建档费用流程、正式 SMTP/U-Mail 发信及附件渠道兼容；本票没有改变邮件附件来源。T23并行变更未纳入本票的共享构建回归结论。
- 不提供在线预览、重命名、替换、单附件恢复或档案附件临时发信。到期文件只标记并由管理员手动清理。

追溯：US-65～66；R50、R58～R59；AT-18 附件与 WhatsApp 人工记录范围。
