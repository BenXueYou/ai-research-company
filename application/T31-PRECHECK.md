## 正式联调前须提供并确认

1. 正式国内邮箱服务商、SMTP 主机/端口/TLS 或 STARTTLS 模式、真实可用的授权账号；秘密通过受控配置交付，记录中只保留配置项名称及验证结果。
2. 发信地址所属域名与服务商给出的 DNS 要求；查询 SPF、DKIM、MX 的真实记录和生效状态，并确认不会影响现有邮箱。
3. 真实可收信的团队 `replyTo` 邮箱及有权查看该邮箱的人；列出允许的小批量验收收件人、拒投/退信测试地址与发送窗口，明确对方已同意收测试邮件。
4. 测试环境的网络出口及供应商白名单、账号日/小时/单次额度、附件格式及大小限制、退信/投递证据获取方式和保留期限。
5. 真实 SMTP 配置验证、发送、证据核对适配器的实现与接入，先在独立配置、数据库、端口和输出目录验收；不得把当前默认适配器的状态标为真实可用。

## 条件齐全后的证据矩阵

| 场景 | 要保存的证据与判断边界 |
|---|---|
| 连接与认证 | DNS 记录、网络出口、TLS 协商版本/证书、服务商认证结果和时间；日志脱敏。 |
| 最小真实发送 | 本次编辑和公共模板附件各一封或经批准的更小样本；记录选择快照、最终邮箱、联系人内部 UUID、`mailsouId`、独立 `id`/`fileId` 值、渠道/回复地址来源、SMTP 命令结果、供应商消息标识及实际收件箱结果。SMTP 受理只证明已提交发信服务。 |
| 回复实收 | 由验收收件人回复，团队回复邮箱原邮箱中核对收件人、主题、时间及消息标识；不以应用自动同步或客户状态变化代替。 |
| 拒投、退信、不确定 | 分别保留 SMTP 明确拒绝、服务商退信/查询、超时或断线时提交是否发生的原始证据；未知状态保留预占，不自动重发。只有可靠逐收件人投递证据才标“有证据送达”。 |
| 额度与跨日 | 在获准发送窗口内记录北京时间额度日、预占/已用/释放及两渠道共享情况；未执行跨日暂停并由原发送人次日重确认，不明尝试保留原日额度，迟到证据只核对原日。 |

真实 SMTP 认证/TLS、DNS/SPF/DKIM/MX、网络出口、服务商限额、真实投递与退信、回复实收、附件兼容、供应商证据的可靠性和跨真实北京时间零点的额度行为均未验证。T19/T22/T24/T25 的本地受控测试结果不扩大为这些结论。
