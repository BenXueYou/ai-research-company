# T29 交付与验收记录

范围：US-83～85、R37～R39/R68～R69、AT-23 中已经确定且可由可控上游响应验证的部分。

## 已实现

- 平台工作台读取共享上游账号最近一次余额、有效期、traceId、获取时间及调用计数。刷新须由平台运营显式操作，GET 页面不触发上游请求。
- `/v2/account` 使用现有 Redis 共享令牌及业务类限额；账号调用和取令牌均计入业务类次数。数据类免费查询沿用现有共享计数；每分钟安全阈值 180（低于供应商 200 上限），数据类每天 30000，业务类取账号配置。不把本地计数称为供应商返回的剩余次数。
- 账号查询事件持久化记录路径、结果、异常分类、traceId 和耗时，不保存 apiKey、Authorization、令牌、密码或客户查询条件。将 40304 点数不足与 40101 每日次数耗尽分开显示。
- 上游失败保留最近成功快照，不改内部点数。终端本地档案仍通过原企业隔离接口读取，现显示最近获取时间；没有自动付费刷新。

## 实际执行

- `npm run build`：通过（含 Vue/服务端类型检查）。
- `node --test dist/tests/upstream-monitor.test.js`：在独立 PostgreSQL 测试库通过。真实 HTTP + 鉴权 + 数据库事务场景确认平台可读、终端被拒、页面读取无外部调用、主动刷新调用 `/v2/access-token` 和 `/v2/account`、失败后快照保留、内部点数 `77.0000` 及查询流水不变、凭据未进入响应。
- Playwright `playwright.t29.config.ts`：在独立 PostgreSQL 测试库通过。平台登录后看到空快照，按钮操作后看到余额、traceId 与分类计数。
- 选择到提交：本票刷新无用户选择的企业标识或地址。`/v2/account` 没有企业参数；公司搜索和详情请求的参数取值来源与标识映射未改。
