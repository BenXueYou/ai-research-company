- 原型成员角色为业务员/终端企业管理员，正式文档沿用既有范围；API枚举严格为`sales/admin`，平台/分销不参与成员开户。创建权限只属于启用的终端企业中已完成改密的管理员。
- 本轮用户明确：本人和首位管理员不可停用，可停用本企业其他管理员及业务员。已同步Spec、PRD、技术设计。首位管理员由组织开户持久化关系`organization_openings.account_id`认定，不能按姓名、最早时间或任意admin角色猜测。

## 实现与接口

- `GET /api/members`：当前企业成员的姓名、邮箱、角色、启用状态及停用能力；不返回密码、密码摘要、会话或其他企业资料。无权限请求拒绝。
- `POST /api/members`：只接受`name,email,role,requestId`。姓名非空且保留原提交值；邮箱复用T01仅折叠域名规则，保留本地大小写、加号、圆点，不裁剪。组织来自锁定后的当前账号，未知组织/目标/密码/电话/状态字段拒绝。成员无需电话。
- 账号、请求幂等记录及成功审计同事务；邮箱沿用全平台数据库唯一键，覆盖不同企业管理员并发抢占和T02组织开户冲突。操作者/请求ID判重，同请求重试返回409，不回放凭据或创建第二账号。响应丢失时先核实列表，补发留给T04。
- 服务端复用密码学随机24字符临时密码和scrypt加盐摘要，72小时有效，创建置必须改密。前端当次内存展示并复制邮箱与临时密码，复制失败允许重试，不再次提交；关闭、账号设置、退出或刷新销毁展示。未在日志、审计、截图、数据库明文或失败DOM工件中保留临时密码。
- `POST /api/members/disable`只接受`accountId`，服务端校验目标属于当前企业、角色范围以及本人/首位管理员禁用边界。事务中停用、删除全设备会话、记录审计；重复停用安全返回。没有恢复启用入口。账号、成员创建关系与历史审计保留，不删除业务历史。
- 操作者和停用目标按ID稳定顺序加锁，随后重新校验真实会话、账号与组织状态。与T01登录/改密、T03创建采用相同账号锁；改密不会把停用账号改为启用。新库初始化增加姓名、成员幂等表与审计表，重复初始化不覆盖账号凭据。

## 参数来源与业务证据

| 字段 | 链路与核对 |
|---|---|
| name | 独立成员姓名表单→POST原值→accounts.name；不替换为组织名或邮箱 |
| email | `Member.UI+tag@EXAMPLE.COM`原始表单→仅域名小写的持久化邮箱→当次交付→真实Windows剪贴板→真实登录页。HTTP测试覆盖本地大小写、加号与圆点差异 |
| organizationId | 当前会话账号→事务锁后accounts.organization_id→成员归属。使用不同组织/账号UUID，拒绝客户端组织覆盖 |
| role | 表单sales/admin→运行时白名单→账号角色；平台、分销及大小写变体拒绝 |
| accountId | 服务端新账号UUID→列表实际成员→停用目标；不以组织ID替代，跨企业及未知目标不泄露资料 |
| password | 服务端安全随机→当次成功响应→复制→首次登录/强制改密。电话与发信地址没有成员登录取值路径，本人改密仍取会话目标 |

Windows剪贴板仅测试比较统一CRLF/LF，不转换邮箱、密码值。T03浏览器创建的是新终端企业，企业名称、电话、管理员邮箱、成员姓名、成员邮箱和账号/组织ID使用不同值。未配置或读取真实供应商密钥。
