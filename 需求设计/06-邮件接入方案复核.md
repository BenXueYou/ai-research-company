# 邮件接入方案复核

日期：2026-10-26。状态：依据用户确认的简化方向形成的方案建议，尚未整体定稿；未进行真实账号联调。

## 已确认的边界

- 保留国内邮箱直接发信、域名解析发信两个入口。
- 第一阶段每个终端企业两种渠道各最多配置一套，可设置默认渠道，每批发送选择其中一种（用户已确认）。
- U-Mail 由平台统一采购，按终端企业隔离配置；终端企业只需配合域名验证。第一阶段由平台承担 U-Mail 服务费用，为每个终端企业配置发送额度，暂不向企业单独收取邮件费；后续收费方式另定（用户已确认）。
- 第一阶段两种渠道均配置真实可收信的团队回复地址，客户回复投递到该邮箱，由业务员在原邮箱查看；系统不自动同步收件及回复内容（用户已确认）。
- 业务员查看回复后，在企业档案中手动登记回复摘要、将客户状态改为“已回复”，保留登记人和登记时间（用户已确认）。
- 第一阶段发送状态区分排队中、已提交发信服务、发送失败、结果待确认；只有渠道提供可靠投递结果时才展示“已送达”，不将受理成功或任务发送完成等同于送达（用户已确认）。
- 发信超时且结果不确定时先标记“结果待确认”，不自动重发；核对服务商记录后仍不明确的，提示可能重复发送，由用户决定是否重发（用户已确认）。
- 第一阶段仅提供手动创建并确认发送的单轮邮件，定时发送与自动跟进后置；确认后发送队列继续遵守频控，供应商任务 API 仅执行本次单轮发送（用户已确认）。
- “邮件营销”简化为“邮件发送记录”页面，集中查看批次和结果；写邮件从企业档案选择联系人后发起，不增加独立创建营销任务的步骤（用户已确认）。
- 模板变量缺失或未替换时阻止发送，提示用户补全或修改；校验、预览、补全和邮件发送均不扣本系统内部点数（用户已确认）。
- 第一阶段邮件仅支持模板中已配置的附件，业务员发送时暂不支持临时上传附件；企业档案附件继续用于留档，不自动作为邮件附件（用户已确认）。
- 企业邮件发送额度采用平台配置的每日上限，团队共享，国内邮箱与域名发信两种渠道共用，切换渠道不重置或另增额度；统一按北京时间零点重置，未用额度不累计。具体上限按供应商套餐与联调结果配置（用户已确认）。
- 额度按本批去重后的最终收件邮箱数计算：确认发送时预占，服务商受理后计入已用，明确未提交成功则释放，结果待确认保留预占；此过程不扣内部查询点数（用户已确认）。
- 跨日未执行邮件暂停，解除对应原日期预占，用户次日重新确认后占用新一天额度；已提交但结果待确认的邮件继续归原日期核对，不跨日重复占用额度（用户已确认）。
- 第一阶段由平台统一提供少量公共模板及预设附件，终端企业直接选用，暂不做模板管理页面。选择模板后仅编辑本次邮件内容，保存、预览或发送均不覆盖公共模板；流程为选模板 → 改内容 → 预览 → 确认发送（用户已确认）。
- 发邮件不扣本系统的数据查询点数；上游邮件服务费用不能因此视为免费。
- 同批最终邮箱去重、变量冲突人工选择、个人邮箱不自动兜底等规则沿用《05-需求复核记录.md》。

## 文档核对

来源：[群发终端客户接口V29.pdf](./群发终端客户接口V29.pdf)，共 122 页，版本 V29，标注更新日期 2026-09-08。已提取全文并重点核对第 1、6～9、38、54～65 页，对第 60、65 页进行了渲染检查。

| 位置 | 文档能力 | 方案影响 |
|---|---|---|
| 第 1 页 | 推荐 `/apinew/`；批量营销的 API 路线为上传地址池、模板、建立任务；SMTP 路线主要介绍触发类邮件 | 域名渠道的营销发送优先评估任务 API，不能仅因 SMTP 简单就认定统计能力等价 |
| 第 6 页 | service-info 提供服务状态、有效期和剩余发送额度 | 单独展示邮件服务额度，与腾道点数隔离 |
| 第 6～9 页 | 部分任务统计不适用 SMTP；SMTP 无效地址明细有获取限制 | 不承诺两种渠道拥有相同的退信、统计回写能力 |
| 第 58～63 页 | 域名添加、DNS 验证、域名下发信账号管理及指定客户域名操作 | 域名发信需有效发信账号，DNS 配置本身不是发送服务；客户账号隔离方式需确认 |
| 第 60 页 | DNS 示例含 SPF、MX、DKIM，示例提示 SPF、MX 配置正确才可验证通过 | 建议使用专用发信子域名，避免直接修改在用企业邮箱主域的 MX；实际记录以供应商为该域名提供的配置为准 |
| 第 64～65 页 | HTTPS smtp.php 可提交发信，具有频率限制；from 必须是平台已有 SMTP 账号 | 该接口属于 U-Mail 通道，不等于任意国内邮箱 SMTP 接入 |
| 第 65 页 | 回复地址参数拼写为 relpy_to；tpl_id 同时提供时优先于 subject/content；附件总量上限 40M | 适配时严格按接口契约，不自行修正字段拼写或改变参数优先级 |
| 第 38 页 | 退订接口按 list_id 和 address 操作订阅地址 | 本地允许提示后重发，不代表上游必然接受；退订、黑名单及拒投行为需联调，不设计绕过上游限制 |

文档未证明普通国内邮箱服务商的 SMTP 配置或收信能力，也未证明 U-Mail 发信账号就是可供业务员收信的完整邮箱。

## 已确认：渠道配置数量与选择

每个终端企业的国内邮箱渠道、域名渠道各最多配置一套，可设置默认渠道，每批发送选择其中一种。其他实施建议及未决事项见下文，未进行真实账号联调。

## 配置与接入建议

将原“我的邮箱”收敛为企业管理员维护的“团队发信设置”，业务员共用配置并记录实际操作人。

| 项目 | 国内邮箱渠道 | 域名渠道 |
|---|---|---|
| 接入 | 既有邮箱的 SMTP 服务、端口、加密方式、账号及授权凭据 | U-Mail 服务账号、已验证域名及一个发信地址 |
| 第一阶段数量（已确认） | 最多一个团队邮箱配置 | 最多一个域名发信配置 |
| 配置验证 | 连通性及测试发送 | 域名验证、账号状态及测试发送 |
| 发送入口 | 编写内容、选择收件人、确认发送 | 同一发送页面，明确所选渠道 |
| 回复处理（已确认） | 指定真实可收信的团队回复邮箱，在原邮箱查看 | 指定真实可收信的团队回复邮箱，在原邮箱查看 |

配置数量、默认渠道与按批选择方式已确认。实施建议：不做自动轮换或失败后跨渠道自动重发；每批固定发信身份与渠道，保留本地发送记录、业务操作人、对应档案及供应商返回标识。

域名渠道建议优先采用 U-Mail 群发任务 API；小批量能否满足业务需求、任务创建路径、变量映射、频控、逐收件人结果和失败恢复仍需验证。接口受理或任务发送完成不直接等同于收件箱已送达。
