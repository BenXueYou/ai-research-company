# 控制台角色导航与页面迁移 Spec

版本：v1.2；日期：2026-10-28（Asia/Shanghai）。在 v1.1 的 Vue Router / Pinia 方案上，明确应用根组件的长期职责、兼容容器的过渡性质及逐模块退出与最终删除条件。

状态：整体设计及分批范围已由用户确认；公共 Vue Router / Pinia 基础迁移的实施与验收见 [交付记录](../docs/delivery/application/VUE-ROUTER-PINIA-COMPLETION.md)。平台、分销和终端独立业务页仍按各批次验收。目标分诊标签：`ready-for-agent`；GitHub 发布状态另见 Further Notes。

## Problem Statement

平台运营登录后看到的是按终端入口固定展示的菜单，真实业务组件却按角色全部堆在首页。账号信息、账号设置和退出没有靠右；已改密用户仍被突出提示身份验证完成和修改密码，并看到“后续业务模块尚未开放”的过时文案。菜单大多只是无对应目标的锚点，无法完成实际页面跳转。

用户难以区分下级管理、平台采购、费用、计价、上游状态和异常对账的入口，也难以判断当前状态与待办。各角色的查看范围和操作边界需要在页面组织中明确体现，页面迁移必须保留原有业务契约。

## Solution

四类角色统一设计、分批实施。公共控制台框架提供右上角账号区、按角色展示的导航、真实页面路由、独立账号设置、角色帮助及未提交表单离开提示。业务功能按职责进入列表、详情或配置页面；完整指南进入帮助，必要费用和风险提示留在操作现场。

平台默认进入运营概览，用状态摘要、待处理事项与快捷入口组织首屏。分销默认进入下级管理；终端企业管理员与业务员默认进入找企业。平台与分销可以查看既有授权范围内多层下级的内部点数账户，查看权限与直属交易、密码重置等操作权限分开。

按公共框架与平台、分销迁移、终端迁移三个批次交付；每批独立验证，首批完成不代表后两批完成。

## User Stories

1. As a 登录用户, I want 账号信息、账号设置和退出位于右上角, so that 我能在各业务页一致地找到账号操作。
2. As a 登录用户, I want 仅看到符合当前角色的菜单、子页面和快捷入口, so that 我不会被无关业务入口干扰。
3. As a 登录用户, I want 点击菜单进入独立页面并正确高亮当前位置, so that 我能清楚知道正在处理哪项业务。
4. As a 登录用户, I want 刷新、前进、后退和复制链接保留当前页面, so that 我能恢复或分享业务页面位置。
5. As a 登录用户, I want 无权访问的页面和接口都受到权限限制, so that 直接输入地址也不会绕过授权。
6. As a 已改密用户, I want 首页聚焦业务, so that 我不再被身份验证完成、改密大卡片和业务未开放的过时提示干扰。
7. As a 平台运营, I want 登录后进入运营概览, so that 我能先了解平台状态和待处理业务。
8. As a 平台运营, I want 看到平台点数库存摘要, so that 我能判断当前库存情况。
9. As a 平台运营, I want 看到上游剩余点数、有效期和快照获取时间, so that 我能识别数据的新旧及上游状态。
10. As a 平台运营, I want 打开概览仅读取已有数据, so that 页面访问不会自行更新上游状态或触发额外外部业务调用。
11. As a 平台运营, I want 看到需要人工核对的查询并进入对应页面, so that 我能及时处理结果不确定的业务。
12. As a 平台运营, I want 看到待履约点数订单并进入订单页面, so that 我能继续处理履约事项。
13. As a 平台运营, I want 使用直属开户、点数订单、平台采购和异常对账快捷入口, so that 我能快速进入常用操作。
14. As a 平台运营, I want 在下级管理中查看直属下级、开户和详情, so that 我能集中维护直属合作关系。
15. As a 平台运营或分销管理员, I want 在下级详情中定价和按权限重置管理员密码, so that 我能完成直属业务且不混淆查看与操作范围。
16. As a 平台运营或分销管理员, I want 直属下级列表展示点数摘要, so that 我无需逐个打开详情即可了解账户情况。
17. As a 平台运营或分销管理员, I want 在下级账户页查看授权范围内多层下级的余额、查询冻结、销售预留和可用点数, so that 我能了解下级账户且保留既有查看范围。
18. As a 平台运营, I want 在业务数据查看页按授权组织查看客户档案和邮件记录, so that 我能进行全链运营核对。
19. As a 平台运营, I want 全链查看与跨企业写入及跨级交易权限明确分开, so that 查看能力不会意外扩大操作权限。
20. As a 平台运营, I want 在点数与账务中进入点数订单, so that 我能处理直属订单而无需在首页寻找表单。
21. As a 平台运营, I want 在点数与账务中处理平台采购与平台承担费用, so that 我能按账务职责登记和核对资金及库存。
22. As a 平台运营, I want 查看交易与利润及账务流水, so that 我能核对销售毛利、平台承担费用及业务结果。
23. As a 平台运营, I want 在上游与对账中查看腾道账号状态、额度和有效期, so that 我能集中监控上游服务。
24. As a 平台运营, I want 主动更新上游状态, so that 外部状态获取仍由明确操作触发。
25. As a 平台运营, I want 在上游与对账中处理查询异常和迟到结果, so that 我能沿用既有依据与结算规则完成核对。
26. As a 平台运营, I want 在平台设置中维护接口单价、点数换算系数及最低加价率, so that 我能把计价配置与采购账务分开管理。
27. As a 平台运营, I want 在平台设置中维护 U-Mail 资源和企业邮件日额度, so that 我能集中处理平台邮件配置。
28. As a 分销管理员, I want 登录后进入下级管理, so that 我能直接处理主要合作业务。
29. As a 分销管理员, I want 导航保持下级管理、点数订单、交易与利润三个入口, so that 我能按业务闭环找到功能。
30. As a 分销管理员, I want 在点数订单中创建订单、确认收款并继续预留、完整划拨或合规退款流程, so that 页面拆分不会打断履约。
31. As a 分销管理员, I want 查看授权交易、利润和自有账务对账, so that 我能核算业务而不获取下级客户内容。
32. As a 分销管理员, I want 多层下级只读查看与直属业务操作分开, so that 我不会误以为查看组织就能跨级开户、定价、交易或重置密码。
33. As a 终端企业管理员或业务员, I want 登录后进入找企业, so that 我能从国家、产品词或公司名搜索开始获客。
34. As a 终端企业管理员或业务员, I want 使用找企业、企业档案库、邮件发送记录、团队发信设置、成员管理、点数用量六个入口, so that 我能在稳定导航中找到业务。
35. As a 终端企业管理员, I want 在对应页面维护团队发信设置和成员, so that 我能管理本企业协作能力。
36. As a 业务员, I want 查看既有权限允许的共享数据而不能维护团队设置或成员, so that 页面入口不扩大我的权限。
37. As a 终端企业用户, I want 页面拆分保留搜索、身份核实、建档、联系人选择及单轮邮件流程, so that 我能连续完成获客业务。
38. As a 终端企业用户, I want 收费查询仍逐步确认且保留原参数来源, so that 导航变化不会造成额外扣费或误操作。
39. As a 登录用户, I want 在独立账号设置页修改本人密码, so that 我能主动维护凭据。
40. As a 登录用户, I want 主动改密保留当前密码验证、两次新密码校验及成功后退出重登, so that 安全契约保持一致。
41. As a 使用临时密码的用户, I want 只能进入强制改密或退出流程, so that 我在改密前不能通过直接链接进入业务。
42. As a 登录用户, I want 从账号设置返回此前业务页面, so that 我能继续处理原业务。
43. As a 登录用户, I want 帮助中心按角色展示操作指南、规则说明和常见问题, so that 我能获得与当前职责相关的帮助。
44. As a 登录用户, I want 操作所需费用确认、风险提示和错误说明仍在业务页面展示, so that 我无需跳转帮助才能安全完成操作。
45. As a 填写表单的用户, I want 离开有未提交内容的页面时选择继续编辑或放弃修改, so that 我不会因切换菜单、返回或后退丢失输入而不知情。
46. As a 已提交请求的用户, I want 页面切换不被当作业务取消, so that 结果未确认的请求仍沿用既有核对与防重复机制。
47. As a 项目维护者, I want 分销和终端迁移被明确记录为独立后续批次, so that 公共框架完成后不会遗漏剩余页面。
48. As a 项目维护者, I want 每批记录参数对照、权限拒绝、业务结果及未验证流程, so that 我能判断迁移是否保留原有契约。

## Implementation Decisions

### 角色导航与页面边界

| 角色 | 默认页面 | 主导航及职责 |
| --- | --- | --- |
| 平台运营 | 运营概览 | 运营概览、下级管理、点数与账务、上游与对账、平台设置、帮助中心 |
| 分销管理员 | 下级管理 | 下级管理、点数订单、交易与利润；侧栏底部帮助入口 |
| 终端企业管理员 | 找企业 | 找企业、企业档案库、邮件发送记录、团队发信设置、成员管理、点数用量；侧栏底部帮助入口 |
| 业务员 | 找企业 | 共用终端六入口；仅展示既有权限允许的数据和操作，不授予团队设置或成员维护权限；侧栏底部帮助入口 |

- 角色依据当前认证会话，不通过菜单名称或 URL 推断。平台、分销、终端之间的入口按角色区分；业务员与终端管理员共用六入口，维护权限分别处理。任何只读展示也必须受既有服务端授权约束。
- 公共框架负责账号区、导航、业务内容容器和当前位置反馈；业务页面承载各自的列表、详情及表单。正常业务首页移除突出改密卡片及业务未开放的过时提示，主动改密入口保留在右上角。
- 平台下级管理包含直属列表、开户、下级详情与定价、管理员密码重置、下级账户及业务数据查看；后两项查看范围不得被直属操作范围误收窄。
- 平台点数与账务包含点数订单、平台采购与费用、交易与利润、账务流水。采购入账、平台承担费用保留现有业务区分与关联核对，不因页面归组混为同一账项。
- 平台上游与对账包含上游账号监控、查询异常人工核对与迟到结果处理。
- 平台设置包含腾道接口点数单价、点数换算系数、最低加价率、U-Mail 资源及企业邮件日额度。平台采购与计价的现有混合展示按上述职责拆分。
- 平台业务数据查看为既有全链查看能力的页面归位，不赋予跨企业修改、删除、发信、跨级交易或跨级密码重置权限。分销不获得下级关键词、企业、联系人或邮件内容。
- 账户字段区分内部点数余额、查询冻结、销售预留、可用余额和上游点数；禁止混用或将不同账户余额简单相加作为新业务指标。

### 运营概览

- 状态摘要展示平台点数库存、上游剩余点数、有效期及上游快照获取时间。缺失、未配置或读取失败不伪装成零余额或正常状态；具体摘要复用已有业务数据含义，不新增阈值或账务算法。
- 待处理事项包括需人工核对的查询及待履约点数订单；状态口径沿用既有业务状态，不新增枚举或变更处理条件。
- 快捷入口为直属开户、点数订单、平台采购、异常对账，按角色和既有权限展示。
- 概览仅提供摘要和跳转，不承载完整业务表单或明细。读取已有系统数据及历史上游快照；更新上游状态仍由用户主动触发。导航、刷新不得自动授权收费查询或重复外部调用。

### 路由与公共交互

以下为已确认的浏览器 URL 契约，不是源代码文件位置：

| 区域 | 已确认页面路径 |
| --- | --- |
| 平台 | `/platform/overview`、`/platform/organizations`、`/platform/ledger`、`/platform/reconciliation`、`/platform/settings` |
| 分销 | `/distribution/organizations`、`/distribution/orders`、`/distribution/profit` |
| 终端 | `/terminal/search`、`/terminal/profiles`、`/terminal/emails`、`/terminal/sending-settings`、`/terminal/members`、`/terminal/usage` |
| 公共 | `/account/settings`、`/help` |

- 采用 Vue Router 的 `createRouter()` + `createWebHistory()`，由 Router 统一管理 URL、导航和页面匹配。保留上述 URL 及已接入的 `/platform/reconciliation/upstream`；列表、详情和各子页面的具体子路由在实施时依据已确认职责补齐，包括平台点数订单，不能因尚未指定路径而遗漏功能。
- 运行与部署入口须支持合法前端路径的直接访问和刷新；静态资源与未知 API 请求不能被错误回退成成功的 HTML 页面。前端路由守卫不能替代服务端业务接口鉴权。
- 已登录用户登录后进入其角色默认页面。访问未授权路径时拒绝访问或返回角色默认页，不能挂载或读取无权业务数据；未登录与强制改密状态继续按既有身份契约处理。
- 账号设置提供本人改密，验证当前密码、新密码和确认密码，沿用已批准密码规则与会话失效策略。成功后退出并重新登录；取消或返回时回到此前合法业务页面，不把“返回原页”解释为改密后保留旧会话。
- 帮助按角色展示开户、交易、计费、发信与账号管理指南；完整说明移入帮助，操作现场仍保留必要费用确认、风险提示及校验反馈。
- 开户、采购、订单和配置表单存在未提交内容时，菜单切换、返回及浏览器后退提示“继续编辑／放弃修改并离开”。首版不新增跨页面草稿保存。
- 已提交且结果未确认的请求保留既有幂等、核对及防重复提交机制；页面卸载或路由切换不等于取消、退款、释放预留或请求重试。

### Vue Router 与 Pinia 技术方案

#### 选型及依赖边界

| 能力 | 决策 | 原因与范围 |
| --- | --- | --- |
| 路由 | 引入 `vue-router`，使用显式路由表与 HTML5 History | 已有多角色、独立页面、深层链接和离开确认；统一匹配、导航与守卫，替换 App.vue 手写 History 逻辑 |
| 跨页面状态 | 引入 `pinia`，首批只建立会话 store | 账号区、路由守卫及业务页面共享同一份服务端会话与初始化状态，避免各自请求或维护副本 |
| Pinia 持久化插件 | 不引入 | 当前无跨刷新草稿需求；会话由服务端 Cookie 验证，刷新重新读取会话，密码及业务数据不写入 localStorage / sessionStorage |
| 服务端数据缓存、自动重试库 | 暂不引入 | 保留已有请求与刷新机制，避免默认重试、重新挂载或窗口聚焦触发额外查询及外部调用 |
| 自动生成路由、权限插件、全局事件总线 | 暂不引入 | 当前显式路由、类型化元数据和组合式函数足以覆盖需求，后续有明确场景再评估 |

Pinia 是 Vue 状态管理库，额外的 Pinia 插件不是本次必要依赖。实施时核对新增依赖与当前 Vue、TypeScript、Vite 的兼容性并锁定版本，不同时升级无关依赖；本次文档修订不修改包或锁文件。

#### 路由组织与会话门禁

- `web/router/index.ts` 创建 Router；按平台、分销、终端与公共页面拆分路由配置。`App.vue` 保留应用根容器，控制台布局承载账号区、侧栏与 `RouterView`；独立业务页面按领域就近放置。
- 每个路由具有唯一名称；类型化 `meta` 表达标题、角色范围和导航归属。菜单由路由配置或同源导航描述派生，不再各自维护允许路径集合；页面是否显示操作仍按原有业务授权判断，不以角色菜单替代权限。
- 普通链接使用 `RouterLink`；业务跳转使用 `router.push/replace`，当前页面使用 `useRoute()`。移除重复的 `path` 状态、自行监听 `popstate` 和直接操作 `window.history` 的导航代码。标题、高亮、父级菜单及滚动恢复交由路由配置和 `scrollBehavior` 统一处理。
- 路由守卫等待会话初始化完成后再决定是否进入受保护页面；等待期间不挂载业务页、不发业务请求。未登录、强制改密和正常会话分别显示既有登录、强制改密与业务界面，不因技术迁移新增对外登录 URL。强制改密不能被帮助、账号设置或业务深链绕过。
- 保留当前登录成功进入角色默认页的规则；已有会话直接访问合法链接时保留目标页。非法或无权路径沿用拒绝或角色默认页规则，不产生循环重定向；账号设置返回值只接受当前角色合法的站内业务位置。
- `beforeEach` 处理会话与角色准入；页面级 `onBeforeRouteLeave` 处理未提交内容；同一组件内路由参数改变时使用 `onBeforeRouteUpdate` 核对离开与加载逻辑。刷新和关闭窗口继续用 `beforeunload`。取消导航须同时保留 URL、页面、表单和历史位置，不再手动 pushState 补偿浏览器后退。
- Vite、Nest 静态入口及部署反向代理同步承载合法前端路径，包含上游监控深链及后续详情路径；开发与生产行为分别验证。只给合法前端 GET/HEAD 请求回退 HTML，未知 API、缺失静态文件和未知路径保持各自错误响应；引入 Router 不能替代服务端 History 配置。

#### 状态归属与请求边界

| 状态 | 所属位置 | 约束 |
| --- | --- | --- |
| 当前路径、路由参数、已批准的可分享筛选条件 | Vue Router | 不在 Pinia 再维护一份当前路径；筛选进入 URL 须逐项核对默认值及请求来源，不在本次统一改造 |
| 当前会话、初始化状态、角色及 mustChange | `web/stores/session.ts` | 服务端会话为唯一认证依据；保留 id、email、loginName、role、mustChange 字段含义，不新增客户端授权事实 |
| 密码、表单输入、选择项、报价、提交中及结果未确认状态 | 所属页面或现有业务模块 | 不全量搬入全局 store；维持既有生命周期、防重及业务取值；不缓存密码页面 |
| 列表、详情、余额、额度、快照及错误反馈 | 所属领域页面 / composable | 沿用现有请求语义，不为导航统一增加缓存、预取、轮询或重试 |

- `main.ts` 先安装 Pinia 再安装 Router，等待 Router 首次就绪后挂载；守卫通过同一 Pinia 实例访问 session store，避免在模块导入时依赖尚未安装的 store。
- 会话初始化合并并发请求，区分未初始化、加载中、已登录、未登录和读取失败。网络失败不伪装成已退出，不无限重定向；重试不触发业务操作。HTTP 请求封装保留现有方法、Cookie、CSRF、错误和参数契约，不由 store 或守卫添加业务重试。
- 成功退出、成功改密导致退出或收到 401 时，清除会话、业务内存状态和页面缓存。会话失效应绕过普通表单离开确认，不能因取消确认继续显示旧业务数据；不因此触发业务取消或重发。
- 会话初始化和业务异步响应均需防止旧请求在退出或换账号后回写新会话，可采用会话代次标识忽略过期响应。角色和账号切换后不复用前一账号的页面实例或请求结果。

#### 应用根组件与兼容容器的职责及退出条件

Vue Router 负责 URL 匹配、页面选择和导航，不替代 Vue 应用根组件。保留 `App.vue` 作为本仓库应用根入口；文件名称本身不是框架限制，也不要求将所有公共逻辑写在一个文件中。`main.ts` 安装 Pinia / Router 并挂载应用，路由模块处理会话及角色准入守卫，会话 store 管理认证状态；`App.vue` 组合身份界面、公共布局和路由出口，公共布局与所属页面分别承接其职责范围内的展示、表单离开保护和缓存。业务页通过 `RouterView` 渲染，不重新集中堆入 `App.vue`。

`CompatWorkspace.vue` 不是 Vue Router 的必需设计，也不是长期业务布局。它仅在分批迁移期间承载尚未完成独立路由接入的旧模块，保留既有角色条件、组件实例、表单及结果未确认上下文，避免切换菜单时因重新挂载产生额外请求或丢失业务状态。当前部分路径仍指向 `EmptyRoute.vue`，实际内容由兼容容器及 `target` 锚点定位；建立 URL 或引入 Router 不等于完成页面迁移，不能据此直接删除兼容容器。

每个业务模块迁移票必须同时完成以下退出检查：

1. 路由绑定真实页面，核对兼容容器中的原组件、角色条件、参数来源及跨组件事件依赖；同一业务不同时由新页面和旧兼容实例挂载或发请求。
2. 明确页面离开、返回、参数更新和会话切换的生命周期策略；保留所需草稿、请求标识、幂等及结果核对上下文。确需保留实例时使用限定范围的缓存，不统一缓存所有页面，也不将缓存视为跨刷新恢复。
3. 新页面接入时同步移除该模块在兼容容器中的旧挂载，以及仅为该模块服务的 `target`、兼容路径判断、滚动定位及手写导航；仍有调用方的共享逻辑继续保留，不能提前整段删除。
4. 记录迁移前后请求参数值与来源，适用的不同标识字段使用不同测试值；验证权限允许与拒绝、业务结果、切页返回、深链直达刷新及前进后退，确认无额外业务请求、收费操作或重复提交。交付记录列明已验证和未验证流程。

全部角色的兼容模块均已完成真实路由迁移及相关业务验收，且没有剩余挂载、调用方和锚点依赖后，删除 `CompatWorkspace.vue`、其导入和挂载、`workspaceVisited`、`isCompatPath` 及剩余兼容专用逻辑。最后一个移出兼容容器的模块票负责核对全局剩余引用并完成清理、汇总验证；若仍有未迁移模块，不以单票完成宣布全局清理完成。公共框架票 #34 规定该退出标准，各业务迁移票落实所属模块的移除及验收。最终结构为 `App.vue → 公共布局 / RouterView → 当前业务页面`，保留应用根组件，退出过渡兼容容器。

#### 分批迁移与页面生命周期

1. 先记录当前工作区基线与受影响参数链路，在第一批内部独立完成 Router、Pinia 会话、公共布局、身份门禁及 History 承载，验证四角色身份和导航后再继续业务拆页。
2. 未迁移的分销和终端页面暂由明确的兼容容器承载，保持既有实例和状态边界；同一兼容容器的路径切换不得重新挂载整个工作区。不得同时挂载兼容模块与其已迁移独立页，避免重复请求。兼容容器仍是过渡实现，菜单定位不算独立页面交付。
3. 按既定三批逐域拆页，逐个核对 `onMounted` 请求、卸载副作用及返回行为。确需保留的页面实例用有范围的 `KeepAlive` 或继续保留兼容实例；不得给所有页面统一套缓存或用 fullPath 作全局 key。缓存停用时暂停不必要监听，恢复时不自动重放收费操作，退出时销毁缓存。
4. 结果未确认业务在所属模块继续保留原请求标识、幂等及核对上下文；不能因改用 Router 丢失它，也不能将 `KeepAlive` 当作跨刷新恢复方案。每条受影响流程先确定生命周期策略并验证，再移出兼容容器。完成各批后移除对应兼容锚点和手写导航。

## Testing Decisions

### 主要验证入口

- 以浏览器驱动真实后端及专用 PostgreSQL 测试数据库的端到端场景为主要入口；从用户操作验证页面、HTTP 参数、权限与业务结果。复用既有应用装配、测试数据库和受控供应商适配器，避免为各组件另造测试接口。
- 测试边界承接用户已确认的“参数来源、权限、提交结果、其他角色登录及强制改密回归”。必要的 HTTP 权限拒绝和账务/外部调用断言作为该入口的补充，不把只测组件挂载或内部函数调用视为验收。
- 现有组织停用与恢复浏览器场景已提供登录、强制改密、直属开户、请求捕获和真实落库校验先例；已有邮件发送及档案附件浏览器场景可复用角色和租户隔离验证方法；身份、组织、订单、采购和报表服务测试可作为业务断言先例。各测试的现有脚本覆盖范围须在实施时核对，不能把常规脚本视为全量覆盖。

### 必须覆盖的外部行为

| 场景 | 验收结果 |
| --- | --- |
| 四角色登录、不同角色切换 | 默认页面及菜单正确，不残留前一角色的数据或操作；业务员共用六入口但不能维护团队设置和成员 |
| 顶部账号区与正常首页 | 账号操作靠右；正常首页无突出改密卡片和业务未开放过时提示；主动改密仍可访问 |
| 路由点击、直达、刷新、前进后退、复制链接 | 页面与 URL、高亮对应；合法深层路径刷新成功；未知 API 不返回前端 HTML |
| Router 首次进入及会话初始化 | 并发入口共享初始化；会话确认前不挂业务页；读取失败可恢复且无跳转循环；登录仍进入角色默认页 |
| Pinia 会话清理与异步竞争 | 退出、改密成功、401 和账号切换后不显示旧数据；旧请求晚到不恢复旧会话或覆盖新账号；失败不自动重发业务请求 |
| 缓存页面、兼容容器与实例复用 | 切换账号设置及返回保留既有业务上下文；未迁移工作区不重复挂载；已迁移页不与旧模块重复请求；收费查询、邮件、订单不因激活或返回重放 |
| 取消导航、参数变化及刷新承载 | 点击、后退、前进及同组件参数变化均验证继续编辑 / 放弃；取消时 URL、历史、表单一致；Vite 与生产入口覆盖上游监控和已实现详情深链；缺失静态文件不返回 HTML |
| 未登录、无权角色、强制改密直达业务页与直接请求接口 | 沿用身份及权限拒绝；前端隐藏之外服务端仍拒绝，不能读取无权数据 |
| 概览正常、未配置、无快照、读取失败 | 摘要含正确单位与快照时间；未知状态不表示为零或正常；跳转进入相应页面 |
| 概览读取与导航重复进入 | 不触发上游状态更新、额外收费查询或自动重试；主动更新仍由用户触发 |
| 直属账户摘要、多层账户查看 | 余额、查询冻结、销售预留、可用余额与既有账务一致；保留授权多层查看且拒绝越权组织 |
| 平台业务数据查看与分销访问 | 平台按授权查看档案与邮件；拒绝未经授权跨企业写入；分销页面、响应及导出不泄露客户内容 |
| 开户、定价、订单及密码重置 | 直属操作边界有效；参数及目标正确；凭据交付、校验、收款、预留和履约结果与迁移前一致 |
| 采购、费用、计价、上游核对与配置 | 页面归位后用途、费用关联、计价条件、系数规则、权限与账务结果保持一致 |
| 账号设置、返回及主动/强制改密 | 返回此前合法业务页；当前密码与新密码校验有效；成功后旧会话失效并重新登录；强制流程不可绕过 |
| 未提交表单离开 | 菜单、返回、后退均可继续编辑或放弃离开；继续编辑保留输入，不触发业务提交 |
| 已提交但结果未确认时切页与返回 | 不自动取消、退款、释放库存、重发或重复扣费；沿用已有幂等与核对机制 |
| 终端后续迁移 | 逐步费用确认、身份核实、候选与联系人选择、邮件渠道、变量及额度规则保持一致；确认、取消、失败与重复提交路径均覆盖 |
| 帮助与必要操作提示 | 按角色显示相关指南；费用确认、风险、错误及操作必需说明仍在业务页面 |
