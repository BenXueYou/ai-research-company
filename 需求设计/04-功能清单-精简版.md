1. **编号与完整版清单一一对应**（如 `K-03`、`M-11`），便于对照追溯；被移除的项保留编号并标注 ❌，不静默消失。
2. **处理标记**：
   - ✅ 保留，进 MVP
   - 🔶 保留进 MVP，但**简化实现**（说明列注明简化方式）

## 二、系统设计层面的简化（比砍功能更重要）

| # | 设计决策 | 完整版方案 | 精简版方案 | 连锁收益 |
|---|---|---|---|---|
| 1 | **租户模型（v1.1 重构）** | 多租户，企业→部门→成员三级 | **分销树多租户**：平台 → N 级分销（上限建议 3 级）→ 终端企业 → 成员；业务表挂 `tenant_id`，账务表挂 `distributor_id` + 物化路径（如 `/1/5/12/`） | 终端企业内不做部门级；**节点归属一经开户不可迁移**（历史账务不可改），树调整只做新开户 |
| 2 | **权限模型（v1.1 重构）** | 三角色 + 行级数据权限 | **四角色 + 双层数据域**：平台超管/分销管理员/终端管理员/业务员；**业务域**（线索/档案/沟通/邮件）按终端企业行级隔离、企业内全员可见、**分销节点不可见下级业务数据**；**账务域**（账户/划拨/消耗/牌价）按分销树向下可见 | 「分销看不到下级客户资料」本身就是分销招商卖点；业务域权限校验简化为单 `tenant_id` 过滤 |
| 3 | **检索引擎** | PG + Redis + **ES** + 对象存储 | **PG（`pg_trgm` 索引）+ Redis + 对象存储**，ES 延后到数据量上来再引入 | F-01 环境减负；C-01 检索 MVP 用 PG 足够（落库量级百万内） |
| 4 | **前端底座** | 自建深色科技风设计系统 | **基于 Ant Design（或同级组件库）深色主题定制**，只沉淀业务组件（高级筛选器、详情抽屉、时间线） | P-01 工作量压缩一半以上 |
| 5 | **CI/CD 与环境** | 多实例部署基线 + 完整流水线 | 单环境 + 部署脚本 + 手动触发 | F-01 简化 |
| 6 | **可观测性** | 指标 + APM + 告警体系 | **结构化日志（全链路 traceId）+ 关键告警**（点数余额、配额、外部接口失败率） | F-13 简化，traceId 底线保留 |
| 7 | **邮件子系统** | 发送 + 追踪 + 多轮自动化 + 多邮箱智能调度 | **发送闭环最小集**：绑定→模板→群发单显→频控→退订→退信；多邮箱 = 绑多个 + 手动选择/简单轮询 | M-06/07、M-02 调度算法延后 |
| 8 | **Agent 形态** | 可配置流水线编排引擎 | **定时任务 + 2~3 个固定流程模板**，每步人工可介入 | 避免自研编排引擎（全清单最重单项） |
| 9 | **沟通记录存储** | 四类沟通 + 附件在线预览体系 | 三类混排（邮件/备注/WhatsApp 登记）+ 附件上传下载（无在线预览） | C-09/C-14 简化 |
| 10 | **邮箱验证** | 自建语法→MX→SMTP 探测体系 | MVP 不做（M-08 退信被动兜底）；V1.0 **优先评估第三方验证 API 一次性集成**，自建作为备选 | S-01~S-03 三项变一项 |
| 11 | **计费架构（v1.1 新增）** | 单一层级点数余额 + 消耗扣点 | **三级点数账户 + 牌价体系**：平台池/分销库存/终端余额；划拨 = 库存转移 + 交易流水；**利润点由定价下限强制校验保证**（售价 ≥ 进价 × (1+最低利润率 m)，m 平台全局可配） | 库存制无坏账；**不做线上支付/提现**（线下结算 + 对账单），不做信用赊销，复杂度可控 |

> ⚠️ **简化不碰的红线**：F-02/03/04/06/07/08/09（腾道静默失败防腐层）、M-11（冷邮件合规）、B-03/D-03（查询前预估）、K-03（归属校验）、C-03/04/05（企业查询正确性）、C-15 的**加密与脱敏**部分。砍这些 = 后续必然返工或出事故。

## 四、模块 2 · 用户管理与多级分销体系（U-01~U-08）→ v1.1 按分销模式重构

> **需求调整（v1.1）**：系统从「单团队工具」升级为「可多级分销的 SaaS 平台」。组织模型从「企业→部门→成员」改为树状：**平台 → N 级分销（上限 3 级）→ 终端企业 → 成员**。核心设计：**业务数据域与账务数据域分离的双层权限模型**——分销节点管钱和开户，但看不到下级的客户资料。

| 编号 | 功能 | 处理 | 说明 |
|---|---|---|---|
| U-01 | 账号密码登录 / 登出 | ✅ MVP | 邮箱 + 密码；不接 OAuth/LDAP/SSO |
| U-02 | 会话管理 | ✅ MVP | Token + 超时自动登出 |
| U-03 | 分销层级与组织树 | ✅ MVP（复活重构） | 树状节点：平台→一级分销→二级分销→终端企业；层级上限 3 级（可配）；节点创建/禁用/搜索；**节点归属一经开户不可迁移**（历史账务不可改） |
| U-04 | 角色权限 | ✅ MVP（复活重构） | 四角色：平台超管 / 分销管理员 / 终端企业管理员 / 业务员；按「功能菜单 + 数据域」二维授权 |
| U-05 | 双层数据权限 | ✅ MVP（复活重构） | **业务域**：线索/档案/沟通记录/邮件按终端企业 `tenant_id` 行级隔离，企业内全员可见，**分销节点不可见下级业务数据**；**账务域**：点数账户/划拨流水/消耗统计按分销树向下可见（物化路径实现） |
| U-06 | 操作审计日志 | ✅ MVP（从 P2 提前） | 涉及钱必须审计：点数划拨、牌价修改、开户/禁用、导出，全部留痕 |
| U-07 | 分销开户管理 | ✅ MVP（**v1.1 新增**） | 上级给**直接下级**开户（分销节点或终端企业）；开户即绑定归属、建点数账户、设初始牌价、生成账务档案 |
| U-08 | 成员管理 | ✅ MVP（**v1.1 新增**） | 终端管理员邀请/停用本企业成员；分销管理员管理本节点操作员；**不做企业内部门级** |

## 十四、模块 12 · 分销计费与成本中心（B-01~B-11）→ v1.1 按「保证利润点」扩展

> **需求调整（v1.1）**：点数流转链为「腾道 → 平台池 → 各级分销 → 终端企业」，每一级加价销售。**利润点由系统机制保证，不靠自觉**：
>
> 1. **定价下限强制校验**：牌价保存时硬性校验 `售价 ≥ 自己进价 × (1 + 最低利润率 m)`，低于下限无法保存；
> 2. **库存制划拨**：上级必须先持有库存才能卖，划拨不超库存、余额不为负——无赊销、无坏账；
> 3. **每笔划拨记毛利**：`毛利 = (售价 - 进价) × 数量`，利润逐级可视、可对账；
> 4. **平台三方对账**：腾道账单 vs 平台池消耗 vs 对一级销售总额对平，防跑冒滴漏。

| 编号 | 功能 | 处理 | 说明 |
|---|---|---|---|
| B-01 | 点数余额展示 | ✅ MVP（改造） | 按账户类型展示：平台池 / 分销库存 / 终端余额；终端侧首页常驻不变 |
| B-02 | 余额告警 | ✅ MVP | 终端余额不足告警其管理员 **+ 直属分销**（对分销是续费商机信号） |
| B-03 | 查询前消耗预估 | ✅ MVP | **红线**：所有计费查询先预估后确认，不变 |
| B-04 | 扣点流水明细 | ✅ MVP | 终端视角不变；按月展示 + `requestTraceId` 对账 |
| B-05 | 按节点/企业统计 | ⏸ V1.0（复活改造） | 原「按成员统计」改为账务域：按下级节点/终端企业统计消耗与交易额 |
| B-06 | 免费接口标注 | 🔶 MVP | 前端静态标注，不变 |
| B-07 | API 调用配额监控 | 🔀 并入 F-06 | 不变 |
| B-08 | 点数账户体系与划拨 | ✅ MVP（**v1.1 新增**） | 三类账户（平台池/分销库存/终端余额）；上级 → **直接下级**划拨；库存校验、余额不为负；划拨单幂等（防重复划拨） |
| B-09 | 定价牌价与利润点校验 | ✅ MVP（**v1.1 新增**） | 每级对直接下级设牌价（元/点）；**强制下限校验 `p ≥ 进价 × (1+m)`**，m 平台全局可配；牌价变更留痕（接 U-06 审计） |
| B-10 | 分销交易流水与利润报表 | ✅ MVP（**v1.1 新增**） | 每笔划拨记录：买卖双方、点数、牌价、金额、毛利；按节点/月度汇总进销存与毛利；导出对账单（线下结算依据） |
| B-11 | 平台成本对账 | ✅ MVP（**v1.1 新增**） | 腾道账单（billing 接口）vs 平台池消耗 vs 对一级销售总额三方对账；平台真实毛利率看板 |
