## 使用入口

终端导航为：**找企业、企业档案库、邮件发送记录、团队发信设置、成员管理、点数用量**。团队发信设置和成员管理仅终端管理员可维护。分销导航为：**下级管理、点数订单、交易与利润**；开户与定价在下级详情，收款、划拨和退款在订单详情。平台运营管理直属下级、平台配置、上游额度与异常对账，并可查看全链账务及业务数据，查看不扩大交易操作权限。

主链：产品词（必选国家与贸易时间，单独确认费用）或公司名免费列表 → 选择候选与身份核对 → 确认详情费用建档 → 档案内按页确认联系人费用 → 选择邮箱/核实归属 → 公共模板与本次内容 → 预览确认单轮发送 → 记录与人工回复摘要沉淀。

## 第一阶段功能


### 基础设施与腾道适配层

| 编号 | 功能 | 交付边界 |
| --- | --- | --- |
| F-01 | 项目脚手架与部署 | 单环境部署脚本；PostgreSQL、Redis、私有对象存储；ES按实际规模后置。技术栈选型不构成已完成实现。 |
| F-02 | 统一响应解析层 | 业务成败只看 success 不看 HTTP 状态码；code 按字符串解析并兼容数字；读 data 前判空；分支判断只用 code 不用 msg；每次调用记录 traceId |
| F-03 | 翻页守卫 | 按各接口实际限制请求前校验；通用贸易上限pageNo×pageSize≤10,000且pageNo≤1,000。每次仅获取经确认的一页，不自动拉全量。 |
| F-04 | 参数构造规范 | 分隔符分派：country（数据源）用逗号、hsCode/国家码等业务字段用分号、联系人 positionTag 用逗号——用错返回 0 条且不报错；国家码强制 ISO Alpha-3；区间参数强制两元素且两端有值；请求 DTO 与响应 DTO 完全分离（请求 sumOfUSD / 响应 sumOfUsd） |
| F-06 | 共享账号配额与限流 | 平台共用腾道账户；跨接口合并200次/分钟，数据类30,000次/日，免费数据接口也占次数；业务类按账号配置。吸收B-07，系统内提示。 |
| F-07 | 查询冻结与结算引擎 | 用户逐页确认最高额度、锁定系数后冻结终端账户；可用不足不调用。按页实际费用汇总换算四舍五入4位且不超上限；不确定保留冻结并人工核对，失败或零结果释放，已扣退回，迟到结果不重扣。 |
| F-08 | 零结果诊断 | 请求前排除参数及页码越界；真实零结果不扣用户点数。不自动扩范围或发起付费重试，保留traceId。 |
| F-09 | 各接口独立 Response DTO | 10+ 接口的列表字段与分页字段互不统一：data.content vs data.list；page/size vs pageNo/pageSize；游标式 vs 页码式；importers-stat/exporters-stat 无数组（data 本身即单聚合对象）；/v2/company 单对象；/v2/contact/{id}/social 直接是数组。禁止写「先试 content 再试 list」的统一兜底 |
| F-10 | 租户与账务数据模型 | 业务表及原始缓存按终端企业隔离；同企业共享，平台查看例外，分销商不可看下级业务数据。组织树、订单、销售预留、查询冻结、邮件额度分开建模。 |
| F-11 | 落库去重与请求幂等 | 企业与联系人按既有标识在本企业内去重；联系人mailsouId保持来源。查询授权ID+页码+条件快照防重复执行，不能把主动更新或下一页默认为已授权。批量任务结算边界另定。 |
| F-12 | 字段填充率验证工具 | 上线前必做：针对目标国家地区、数据源与关键字段验证实际填充率，避免功能做完但数据是空的 |
| F-13 | 可观测性 | 全链路 traceId；外部调用记录接口路径、耗时、HTTP 状态、脱敏后参数与错误信息；指标与告警 |
| F-14 | 安全与合规基线 | apiKey / accessToken / 邮箱授权码经密钥管理服务存储，严禁硬编码或进代码仓库；个人数据加密；审计日志框架 |
| F-15 | 异常与本地数据降级 | 只返回本企业已获取数据并标最近获取时间；不因缓存过期自动付费刷新；计费请求超时进入结果确认中，不盲目重试。 |

### 用户与组织权限

| 编号 | 功能 | 交付边界 |
| --- | --- | --- |
| U-01 | 账号密码登录 / 登出 | 邮箱 + 密码，密码加密存储；不接 OAuth/LDAP/SSO |

| U-04 | 四角色与服务端权限 | 平台运营、分销管理员、终端管理员、业务员。全链查看不等于跨级交易；平台默认可看业务数据仅为查看权限例外。 |
| U-05 | 业务与账务数据边界 | 终端企业内全员共享档案，不做成员隔离；企业间含原始缓存隔离。分销商仅看开户、余额、交易及汇总用量，不得通过明细或导出看到查询词、客户、联系人和邮件。平台运营默认可查看业务数据，不自动获得跨企业修改/删除/发信权。 |
| U-06 | 操作审计日志 | 涉及钱必须审计：点数划拨、牌价修改、开户/禁用、敏感操作全部留痕 |
| U-07 | 直属上级开户 | 开户、定价、收款确认、划拨仅直属上级执行；开户后上级不可迁移，换合作另开户，不自动转余额或业务数据。 |
| U-08 | 直接创建与维护成员 | 终端管理员直接创建账号、重置密码、停用成员，不做邀请邮件流程或部门层级。停用保留其档案、人工记录及操作历史。 |

### 企业档案与时间线

| 编号 | 功能 | 交付边界 |
| --- | --- | --- |
| C-01 | 档案库检索与状态筛选 | 企业内共享已建档客户；按线索/跟进中/已回复/无效和统一下次跟进时间筛选，候选留在搜索结果，不设独立线索池。 |
| C-02 | 档案详情与软删除恢复 | 展示源数据、固定补充、联系人、统一时间线及附件。仅企业管理员软删除和恢复档案，业务员可补充修改；留痕。完整贸易统计第二阶段。 |
| C-03 | 国家地区强校验 | 查询企业详情必须带 countryCode3，且入库前校验返回值等于传入值。同名企业在多国都有记录，不传国家码时返回哪条不确定，且接口不报错——这是数据正确性的关键防线 |
| C-04 | 判空处理 | 以 data.id 是否为 null 判断企业是否存在。不可用 contactMethods 或 tradeStats 判空（未匹配时它们返回空数组/全 0，结构完整） |
| C-05 | 名称写法保真 | 按数据源原始写法存储，仅去首尾空格与多余标点。改动写法（改小写、加句点）会显著降低命中率 |
| C-08 | 手动客户状态与标签 | 线索、跟进中、已回复、无效四态由业务员手动调整；邮件提交或送达不推进状态，无效不等于删除。星级标签保留。 |
| C-09 | 统一时间线与记录权限 | 邮件系统记录、手动回复摘要、备注、WhatsApp记录按时间倒序并可按类型筛选。人工记录仅创建人编辑、企业管理员软删除；系统邮件不可手改删，渠道状态由系统核对留痕。 |
| C-11 | WhatsApp手动沟通登记 | 仅沟通时间、联系人或号码、内容摘要、附件四项；无方向/结果/我方账号独立字段；下次跟进时间用档案统一字段。不自动收发。 |
| C-12 | 档案附件上传 | 聊天截图与资料可挂档案或沟通记录。保留原有白名单（jpg/png/webp、pdf/doc/docx/xls/xlsx/ppt/pptx、zip/rar）、≤20MB/文件、≤50/企业；服务端扩展名与MIME校验、私有访问、操作记录。 |
| C-13 | 时间线关联与类型筛选 | 在同一时间线查看邮件、回复摘要、普通备注、WhatsApp；可关联联系人，不再按已取消的方向和结果筛选。 |
| C-14 | 档案附件下载与软删除 | 第一阶段仅上传、下载和企业管理员软删除；无在线预览、重命名或替换。企业内共享、企业间隔离，不自动附到邮件；单附件恢复权限未确认。 |
| C-15 | 脱敏、加密与审计 | 对方 WhatsApp 号码属个人数据：列表页脱敏展示（如 +86 1388000）、存储加密，红线；业务数据权限由 U-05 业务域承担（终端企业行级隔离）；新增、编辑、删除、上传、下载全部写审计日志 |
| C-17 | 固定补充字段 | 主营产品、采购需求、合作意向、下次跟进时间；其他写自由备注。与腾道原始数据分区，记录修改人时间。无自定义字段管理，跟进时间仅展示筛选，不主动提醒。 |

### 邮件发送与记录

| 编号 | 功能 | 交付边界 |
| --- | --- | --- |
| M-01 | 国内SMTP与U-Mail配置 | 每企业国内SMTP和U-Mail域名各最多一套，团队共用并设默认渠道。平台统一采购按企业隔离；企业配合域名验证，第一阶段平台承担U-Mail费。两渠道均配真实可收信回复地址。 |
| M-02 | 单批选择固定渠道 | 每批选择国内SMTP或域名渠道一种，不轮询多个邮箱、不自动切换或跨渠道重发；两渠道共享企业每日额度并各遵守服务商限制。 |
| M-03 | 手动单轮群发单显 | 每个最终收件邮箱仅一封、单显；用户预览后确认一次单轮发送，供应商任务仅执行本轮，不提供定时或自动跟进。 |
| M-04 | 公共模板与本次内容 | 平台预配少量公共模板及附件，无终端模板管理页。选模板后仅改本次内容；保存/预览/发送不回写公共模板。变量缺失或未替换阻止发送且不扣点，附件仅模板预设。 |
| M-08 | 发送状态与不确定结果核对 | 排队中/已提交发信服务/发送失败/结果待确认；可靠投递证据才显示已送达。SMTP/API统计能力不假定一致；超时不自动重发，核对仍不明则提示可能重复由用户决定。回复原邮箱查看后人工登记。 |
| M-09 | 共享每日额度与频控 | 平台配企业日上限，团队两渠道共用，北京时间零点重置不累计。去重最终邮箱数确认时预占；受理转已用、明确未提交释放、不确定保留。跨日未执行暂停释放旧预占，次日重确认；已提交不确定留原日期核对。发送不扣查询点数。 |
| M-11 | 退订标记与确认重发 | 退订仅标记，默认不勾选；允许人工选择并确认提示后重发，不做企业范围或全局强制屏蔽。不能绕过上游退订/黑名单/拒投限制；标记归属范围及政策适用性待验证。 |
| M-12 | 邮件发送记录页面 | 替换邮件营销页，展示批次与逐收件人状态、渠道、实际操作人、关联档案和额度日期；写邮件仅从档案联系人进入。不单独创建营销任务，不自动同步回复。 |

### 点数分销与成本
