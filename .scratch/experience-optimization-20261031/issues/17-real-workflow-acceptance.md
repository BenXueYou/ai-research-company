# 17 — 真实供应商连续流程与费用验收

**What to build:** 在明确授权的小范围真实账号中验证产品词发现、入库、独立联系人及批量查询和自动结算完整链路，给出可用能力及剩余限制。

**Blocked by:** 14 — 接通真实产品词搜索与名单入库；15 — 接通真实账单与查询结果核实能力；16 — 升级副本与连续业务流程集成验收。

**Status:** ready-for-agent

**基线：** 需求基线：《产品需求文档PRD》v3.3、《第一阶段实施规格Spec》v1.3、《技术设计文档》v3.4及《体验优化技术设计与实施依赖》v1.0；遵守仓库现行约定与已批准身份决策。以当前代码和交付证据核对已有能力，保留其他任务未提交修改。

**验收追溯：** AT-07、AT-08、AT-09、AT-10、AT-13、AT-24～AT-31（腾道及受影响业务部分）。

**证据与完成边界：** 对应E01～E08均须核验；正式邮件投递及生产切换需另行明确授权，本票不自动包含。

- [ ] 先核验当前供应商证据、账号权限/有效期及获准的样本、接口、调用次数和费用边界；缺项保留阻塞。
- [ ] 验证无详情但身份和参数充分可直接查联系人；同一企业稳定键自动关联仅开启E04证明的范围，同名歧义仍人工选择。
- [ ] 真实产品词、企业所在国、贸易时间和分页生效，逐请求结果、账单、计费单位及批次额度可逐项对照。
- [ ] 验证部分成功立即可用、费用迟到不锁其他操作、后台结算、失败项手动重试及默认本地复用。
- [ ] 真实可复现边界留正式证据；无法安全复现的故障以受控记录注明，不为验收制造额外收费或重复请求。
- [ ] 汇总AT逐项受控/真实/未验证状态及上线限制；未验证的SMTP/U-Mail正式能力继续保留原边界，不宣称整个平台生产就绪。

**前端交互与页面风格验收：** 沿用当前实际业务页面的导航、页签、列表与详情关系、表单编排、按钮层级及位置习惯、确认与反馈方式、加载/禁用/空态/错误提示、返回与离开保护及响应式布局。新增选择、批量操作、进度及失败项复用现有页面结构和组件模式；不另建任务中心、重排导航或进行视觉改版。沿用 Element Plus 默认控件外观、统一主色 #4356e0 和公共表单布局，保留键盘操作、焦点及原有状态留存约定。仅按已确认需求调整默认选择、显式入库、批次一次确认、独立联系人和费用等待不锁其他操作等行为；逐票列明必要变化，不扩大到其他交互。实施前记录受影响实际页面的基线，交付在宽屏、中间宽度和手机宽度核对前后布局及交互，明确隔离预览与完整业务页面验收的区别。

**交付要求：** 记录实际修改、受影响流程、实际执行命令和结果、尚未验证项。涉及选择至提交的链路，提供标识取不同值的夹具、最终请求值及来源、允许/拒绝结果、调用次数和适用账务证据。静态检查与构建不能替代本票业务验收。
