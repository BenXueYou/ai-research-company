# 01 — 建立可演练的版本化升级与数据保全入口

**What to build:** 维护者能对现有业务库副本预览、执行和核验版本化升级；重复执行及中途失败均保全既有资料和账务。作为必要前置整理，本票通过命令及副本验收，不增加业务页面。

**Blocked by:** None — can start immediately。

**Status:** ready-for-agent

**基线：** 需求基线：《产品需求文档PRD》v3.3、《第一阶段实施规格Spec》v1.4、《技术设计文档》v3.5及《体验优化技术设计与实施依赖》v1.1；遵守仓库现行约定与已批准身份决策。以当前代码和交付证据核对已有能力，保留其他任务未提交修改。

**验收追溯：** AT-26、AT-30及迁移保全门禁。

**证据与完成边界：** 无需供应商证据；仅使用独立可丢弃副本。真实业务库升级不属于本票。

- [ ] 识别现有已知结构并记录baseline、迁移版本和校验和；未知结构或版本内容冲突明确拒绝。
- [ ] 提供升级计划、执行和核验入口及迁移锁；重复执行幂等、失败事务回滚，可从失败处安全继续。
- [ ] 用含档案、联系人、人工记录、附件、邮件、软删除和在途查询的夹具比较关联、内容、余额、冻结、销售预留及历史流水，全部保持。
- [ ] 演练扩展前后回退边界及备份恢复；不得把现有初始化命令用于旧业务库升级。
- [ ] 只交付执行机制和当前基线保护；各业务票自行携带其增量迁移，不提前创建全部未来业务结构。

**前端交互与页面风格验收：** 本票不新增或调整业务页面；如维护升级入口影响既有页面读取或交互，保持现有页面布局、样式与操作方式并验证回归。后续各业务票遵循其写明的风格保持约束。

**交付要求：** 记录实际修改、受影响流程、实际执行命令和结果、尚未验证项。涉及选择至提交的链路，提供标识取不同值的夹具、最终请求值及来源、允许/拒绝结果、调用次数和适用账务证据。静态检查与构建不能替代本票业务验收。
