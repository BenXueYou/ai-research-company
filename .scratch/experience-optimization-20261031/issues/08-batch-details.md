# 08 — 批量详情一次授权、逐项生效与失败项手动重试

**What to build:** 用户选择多个档案一次确认本批详情最高费用，逐个看到结果及进度，部分失败时仅选择失败项重新确认重试。

**Blocked by:** 05 — 同一档案补详情且结果先于费用可用。

**Status:** ready-for-agent

**基线：** 需求基线：《产品需求文档PRD》v3.3、《第一阶段实施规格Spec》v1.4、《技术设计文档》v3.5及《体验优化技术设计与实施依赖》v1.1；遵守仓库现行约定与已批准身份决策。以当前代码和交付证据核对已有能力，保留其他任务未提交修改。

**验收追溯：** AT-09、AT-10、AT-28、AT-29、AT-31。

**证据与完成边界：** 受控计费策略及Adapter可完成闭环；真实逐项上限和结算单位等E02/E06，缺策略拒绝正式报价。

- [ ] 报价持久化项目清单、来源、身份版本、系数、价格/策略版本及上限；本地复用项不重复入收费清单。
- [ ] 确认校验版本与清单，原子冻结总额并记录逐项占用及持久任务；不足或篡改时零供应商调用。
- [ ] 相同requestId幂等，不同requestId的同一活动目标也防重；单项及批次统一执行入口避免重复冻结/扣费。
- [ ] 项目成功立即可用，明确失败释放对应冻结并列原因，unknown不列失败；批次进度与终端冻结/实扣/释放可追溯。
- [ ] 仅所选明确失败项建立有retry_of关系的新批次；收费重试重新一次确认，不重发成功、零结果或处理中项。
- [ ] 持久发送状态配合租约；重启及双worker对sending/unknown先核实不重发，not_sent才可恢复；停用前后分别验证。
- [ ] 锁旧系数、总额/单项封顶、超额平台承担及未发送项暂停重确认均可验证，不锁其他批次。

**前端交互与页面风格验收：** 沿用当前实际业务页面的导航、页签、列表与详情关系、表单编排、按钮层级及位置习惯、确认与反馈方式、加载/禁用/空态/错误提示、返回与离开保护及响应式布局。新增选择、批量操作、进度及失败项复用现有页面结构和组件模式；不另建任务中心、重排导航或进行视觉改版。沿用 Element Plus 默认控件外观、统一主色 #4356e0 和公共表单布局，保留键盘操作、焦点及原有状态留存约定。仅按已确认需求调整默认选择、显式入库、批次一次确认、独立联系人和费用等待不锁其他操作等行为；逐票列明必要变化，不扩大到其他交互。实施前记录受影响实际页面的基线，交付在宽屏、中间宽度和手机宽度核对前后布局及交互，明确隔离预览与完整业务页面验收的区别。

**交付要求：** 记录实际修改、受影响流程、实际执行命令和结果、尚未验证项。涉及选择至提交的链路，提供标识取不同值的夹具、最终请求值及来源、允许/拒绝结果、调用次数和适用账务证据。静态检查与构建不能替代本票业务验收。
