## 公共布局补充需求（2026-10-28）

来源：用户对当前控制台截图的反馈。本补充纳入 #34 公共控制台票据，适用于四角色公共框架及各批次接入的业务页；截图中的运营概览为示例。

### 布局与展示要求

1. 公共框架顶部左侧增加面包屑，右侧保留账号信息、账号设置和退出。面包屑根据当前已授权路由与页面层级展示，覆盖列表、详情、配置、账号设置及帮助等页面；菜单切换、深链直达、刷新及前进后退后均与当前位置一致。可导航的父级沿用现有路由和离开保护，不创建无效链接，不显示无权访问入口。
2. 移除业务内容区顶部仅用于重复显示当前页面名称的大标题，例如截图中的“运营概览”，由公共顶部面包屑表达当前位置。保留具有业务意义的卡片标题、表单分组、详情对象名称、必要说明、费用及风险提示；不将本要求理解为删除所有业务标题。
3. 划分左侧菜单与右侧业务内容两个独立滚动区域。桌面控制台占满视口，公共顶部固定在右侧内容列顶部，业务内容在其下方滚动。菜单超高时在侧栏内部滚动；滚动任一区域均不带动另一区域或整个框架，账号操作与面包屑始终可见。采用正确的高度、收缩和 overflow 约束，避免整页与内部区域叠加滚动、底部内容被裁切；窄屏导航仍可操作，表格等宽内容在所属区域处理横向滚动。
4. 采用现有 Element Plus 组件库的 Container 布局组件（`el-container`、`el-aside`、`el-header`、`el-main`）承载公共框架，并使用 `el-breadcrumb` 表达当前位置。按实际内容嵌套布局，由公共框架统一管理尺寸与滚动边界；Container 组件本身不替代滚动样式约束。复用仓库已有 Element Plus，不另行引入第二套布局组件库。

### 补充验收标准

- [ ] 四角色可访问页面均使用统一顶部面包屑；账号操作保持右对齐，业务区域不再重复展示页面级大标题，业务分组标题和必要提示保留。
- [ ] 验证主菜单到子页面、列表到详情、账号设置及返回、帮助入口、深链直达刷新和前进后退；面包屑、URL、菜单高亮一致。点击可导航面包屑同样执行现有未提交、提交中及结果未确认的离开保护，不绕过权限门禁。
- [ ] 使用超出视口高度的菜单和长业务页面，在浏览器中分别滚动至底部：菜单滚动不改变业务区域滚动位置，业务滚动不改变菜单位置；顶部面包屑及账号区始终可见，底部内容和操作按钮可达，无额外整页纵向滚动。
- [ ] 验证窗口缩放及窄屏：菜单和账号操作可达，面包屑过长时布局可用，不遮挡业务操作；宽表格不撑破公共框架。
- [ ] 布局组件放在 `application/web/layout`，面包屑复用现有路由和导航元数据；仅供单模块使用的业务组件仍放在其页面目录的 `components`。覆盖已迁移页及仍使用兼容容器的页面，后续批次沿用此约定。
- [ ] 仅调整公共布局、重复页面标题及滚动边界，保持现有业务参数来源、标识映射、默认值、权限、校验和提交条件。对受影响的选择到提交流程记录前后参数及来源，不同标识使用不同测试值，验证允许与拒绝路径、业务结果及无额外请求或提交；交付记录列明实际验证和未验证流程，类型检查及构建不能替代浏览器与业务流程验证。

本补充为待实施、待验收要求，不代表当前页面已调整或原票据已经完成。
