## What to build

建立右上角账号区、按认证会话区分的角色导航与默认入口，使用兼容业务容器保持尚未迁移功能可用。

实施批次：第一批：公共框架与平台。依据用户已批准的《控制台角色导航与页面迁移 Spec》v1.0（2026-10-28）与本会话批准的26票拆分；身份规则沿用已批准 T01 身份决策，业务术语与既有契约保持一致。

批次按第一批、第二批、第三批顺序交付。后两批为必须保留的后续工作，公共框架或首批完成不能替代它们；本票 Blocked by 只列真实技术阻塞，不把批次排程伪装为阻塞边。每批完成时汇总本批证据，回归四角色登录、角色切换与强制改密，列出未验证流程。

## Acceptance criteria

- [ ] 平台默认 /platform/overview，菜单为运营概览、下级管理、点数与账务、上游与对账、平台设置、帮助中心；分销默认 /distribution/organizations，菜单为下级管理、点数订单、交易与利润，侧栏底部帮助。
- [ ] 终端管理员和业务员默认 /terminal/search，共用找企业、企业档案库、邮件发送记录、团队发信设置、成员管理、点数用量六入口；业务员入口不授予维护权限。
- [ ] 实现已确认主路径：平台 /platform/overview、/platform/organizations、/platform/ledger、/platform/reconciliation、/platform/settings；分销 /distribution/organizations、/distribution/orders、/distribution/profit；终端 /terminal/search、/terminal/profiles、/terminal/emails、/terminal/sending-settings、/terminal/members、/terminal/usage；公共 /account/settings、/help。子路由可依职责细化。
- [ ] 通过既有可用业务验证菜单、URL、高亮、复制链接、深层路径直达刷新和前进后退；实际运行与部署承载均支持 History 路由，未知 API 与缺失静态资源不回退为成功 HTML。
- [ ] 四角色登录及角色切换不残留上个账号的数据；未登录、无权角色及强制改密状态不能挂载或读取无权业务数据，直接 API 请求仍受既有守卫限制。正常首页移除突出改密卡片、身份完成大卡片及业务未开放过时提示。
- [ ] 兼容承载保留分销、终端及尚未迁移平台业务，不以菜单或路径建立宣称页面拆分完成；账号设置及帮助最终行为分别由相应后续票交付。
- [ ] 迁移前建立受影响契约对照，迁移后记录选择快照、请求字段和值及来源、服务端取值、落库/外部参数和业务结果。实际链路存在的不同标识字段刻意取不同值；保持参数来源、标识映射、权限、枚举、默认值、兜底优先级、校验与提交条件，不自行添加兜底或混入疑似业务修复。
- [ ] 以浏览器驱动真实后端及独立可丢弃 PostgreSQL 测试库验证用户行为；复用现有应用装配、受控供应商适配器和对应身份、组织、订单、采购、报表、查询或邮件测试入口，补充直接 HTTP 允许/拒绝断言。记录余额流水、幂等与外部调用次数等适用结果；构建、类型检查及无关测试不替代业务验收。
- [ ] 记录实际命令、测试环境、场景结果与尚未验证流程，正式供应商联调单独留证；保留其他任务未提交修改，同步受影响规格和交付证据，不自动部署、重启或修改业务规则。

## 公共布局补充需求（2026-10-28）

来源：用户对当前控制台截图的反馈。本补充纳入 #34 公共控制台票据，适用于四角色公共框架及各批次接入的业务页；截图中的运营概览为示例。

### 布局与展示要求

1. 公共框架顶部左侧增加面包屑，右侧保留账号信息、账号设置和退出。面包屑根据当前已授权路由与页面层级展示，覆盖列表、详情、配置、账号设置及帮助等页面；菜单切换、深链直达、刷新及前进后退后均与当前位置一致。可导航的父级沿用现有路由和离开保护，不创建无效链接，不显示无权访问入口。
2. 移除业务内容区顶部仅用于重复显示当前页面名称的大标题，例如截图中的“运营概览”，由公共顶部面包屑表达当前位置。保留具有业务意义的卡片标题、表单分组、详情对象名称、必要说明、费用及风险提示；不将本要求理解为删除所有业务标题。
3. 划分左侧菜单与右侧业务内容两个独立滚动区域。桌面控制台占满视口，公共顶部固定在右侧内容列顶部，业务内容在其下方滚动。菜单超高时在侧栏内部滚动；滚动任一区域均不带动另一区域或整个框架，账号操作与面包屑始终可见。采用正确的高度、收缩和 overflow 约束，避免整页与内部区域叠加滚动、底部内容被裁切；窄屏导航仍可操作，表格等宽内容在所属区域处理横向滚动。
4. 采用现有 Element Plus 组件库的 Container 布局组件（`el-container`、`el-aside`、`el-header`、`el-main`）承载公共框架，并使用 `el-breadcrumb` 表达当前位置。按实际内容嵌套布局，由公共框架统一管理尺寸与滚动边界；Container 组件本身不替代滚动样式约束。复用仓库已有 Element Plus，不另行引入第二套布局组件库。

### 补充验收标准

- [ ] 四角色可访问页面均使用统一顶部面包屑；账号操作保持右对齐，业务区域不再重复展示页面级大标题，业务分组标题和必要提示保留。
- [ ] 验证主菜单到子页面、列表到详情、账号设置及返回、帮助入口、深链直达刷新和前进后退；面包屑、URL、菜单高亮一致。点击可导航面包屑同样执行现有未提交、提交中及结果未确认的离开保护，不绕过权限门禁。
- [ ] 使用超出视口高度的菜单和长业务页面，在浏览器中分别滚动至底部：菜单滚动不改变业务区域滚动位置，业务滚动不改变菜单位置；顶部面包屑及账号区始终可见，底部内容和操作按钮可达，无额外整页纵向滚动。
- [ ] 验证窗口缩放及窄屏：菜单和账号操作可达，面包屑过长时布局可用，不遮挡业务操作；宽表格不撑破公共框架。
- [ ] 布局组件放在 `application/web/layout`，面包屑复用现有路由和导航元数据；仅供单模块使用的业务组件仍放在其页面目录的 `components`。覆盖已迁移页及仍使用兼容容器的页面，后续批次沿用此约定。
- [ ] 仅调整公共布局、重复页面标题及滚动边界，保持现有业务参数来源、标识映射、默认值、权限、校验和提交条件。对受影响的选择到提交流程记录前后参数及来源，不同标识使用不同测试值，验证允许与拒绝路径、业务结果及无额外请求或提交；交付记录列明实际验证和未验证流程，类型检查及构建不能替代浏览器与业务流程验证。

本补充为待实施、待验收要求，不代表当前页面已调整或原票据已经完成。

## 应用根组件与兼容容器退出约定（2026-10-28）

依据用户确认的《控制台角色导航与页面迁移 Spec》v1.2「应用根组件与兼容容器的职责及退出条件」。Vue Router 管理路由，不替代应用根组件；保留 `App.vue` 组合身份界面、公共布局及 `RouterView`，按职责拆分公共逻辑。Pinia / Router 安装位于 `main.ts`，角色准入守卫位于路由模块，会话状态归会话 store。

`CompatWorkspace.vue` 仅为分批迁移保留旧业务实例与上下文，不是 Router 的必需组件，也不是最终布局。URL、菜单或 `EmptyRoute.vue` 占位不能作为独立业务页完成证据。

### 本票补充验收

- [ ] 公共框架保留应用根组件及公共布局、身份门禁和真实路由出口；不把业务组件重新集中堆入 `App.vue`。按 Spec 分清根组件、入口安装、路由守卫、会话 store 与页面生命周期的职责。
- [ ] 逐业务迁移票落实真实页面接入及旧兼容挂载退出；保留尚未迁移模块的角色条件和必要实例状态，不因引入 Router 直接删除整个兼容容器。
- [ ] 维护退出标准：迁移时移除对应旧挂载、专用 `target`、兼容路径判断及滚动定位，不与独立页重复挂载或发请求；验证表单、提交中、结果未确认、权限及会话切换。
- [ ] 全部角色的兼容模块迁移及相关业务验收完成、无剩余调用方后，由最后一个移出模块的票完成全局清理：删除 `CompatWorkspace.vue`、导入与挂载、`workspaceVisited`、`isCompatPath` 及剩余兼容专用逻辑，核对引用并汇总验证。公共框架完成不代表该全局退出已完成。

本补充规定实施与退出验收要求，不表示当前模块已迁移或票据已完成；业务规则、接口契约、原验收项、状态与依赖保持原票约定。
