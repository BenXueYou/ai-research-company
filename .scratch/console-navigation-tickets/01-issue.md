## What to build

建立右上角账号区、按认证会话区分的角色导航与默认入口，使用兼容业务容器保持尚未迁移功能可用。

实施批次：第一批：公共框架与平台。依据用户已批准的《控制台角色导航与页面迁移 Spec》v1.0（2026-10-28）与本会话批准的26票拆分；身份规则沿用已批准 T01 身份决策，业务术语与既有契约保持一致。

批次按第一批、第二批、第三批顺序交付。后两批为必须保留的后续工作，公共框架或首批完成不能替代它们；本票 Blocked by 只列真实技术阻塞，不把批次排程伪装为阻塞边。每批完成时汇总本批证据，回归四角色登录、角色切换与强制改密，列出未验证流程。

## Acceptance criteria

- [ ] 平台默认 /platform/overview，菜单为运营概览、下级管理、点数与账务、上游与对账、平台设置、帮助中心；分销默认 /distribution/organizations，菜单为下级管理、点数订单、交易与利润，侧栏底部帮助。
- [ ] 终端管理员和业务员默认 /terminal/search，共用找企业、企业档案库、邮件发送记录、团队发信设置、成员管理、点数用量六入口；业务员入口不授予维护权限。
- [ ] 实现已确认主路径：平台 /platform/overview、/platform/organizations、/platform/ledger、/platform/reconciliation、/platform/settings；分销 /distribution/organizations、/distribution/orders、/distribution/profit；终端 /terminal/search、/terminal/profiles、/terminal/emails、/terminal/sending-settings、/terminal/members、/terminal/usage；公共 /account/settings、/help。子路由可依职责细化。
- [ ] 通过既有可用业务验证菜单、URL、高亮、复制链接、深层路径直达刷新和前进后退；实际运行与部署承载均支持 History 路由，未知 API 与缺失静态资源不回退为成功 HTML。
- [ ] 四角色登录及角色切换不残留上个账号的数据；未登录、无权角色及强制改密状态不能挂载或读取无权业务数据，直接 API 请求仍受既有守卫限制。正常首页移除突出改密卡片、身份完成大卡片及业务未开放过时提示。
- [ ] 兼容承载保留分销、终端及尚未迁移平台业务，不以菜单或路径建立宣称页面拆分完成；账号设置及帮助最终行为分别由相应后续票交付。
- [ ] 迁移前建立受影响契约对照，迁移后记录选择快照、请求字段和值及来源、服务端取值、落库/外部参数和业务结果。实际链路存在的不同标识字段刻意取不同值；保持参数来源、标识映射、权限、枚举、默认值、兜底优先级、校验与提交条件，不自行添加兜底或混入疑似业务修复。
- [ ] 以浏览器驱动真实后端及独立可丢弃 PostgreSQL 测试库验证用户行为；复用现有应用装配、受控供应商适配器和对应身份、组织、订单、采购、报表、查询或邮件测试入口，补充直接 HTTP 允许/拒绝断言。记录余额流水、幂等与外部调用次数等适用结果；构建、类型检查及无关测试不替代业务验收。
- [ ] 记录实际命令、测试环境、场景结果与尚未验证流程，正式供应商联调单独留证；保留其他任务未提交修改，同步受影响规格和交付证据，不自动部署、重启或修改业务规则。
